# 事务一致性原型

这是 Agent 密码学系统的数据库状态验证内核，只使用合成数据。它验证预算、输出绑定、撤销与恢复的事务规则，不是可部署的密码学服务。

## 完整公开观察协议的可执行设计

上一级的 `public_transcript_model.py` 将动态查询、控制确认、轮询、计数/直方图结果、重试、跨接收者传输、过期终止和最终事件序列纳入同一个逻辑记录。正常模拟器只能接收公开配置及绑定动作的已批准机制结果，拒绝原始数据参数。第二次查询可在收到第一次结果后选择计数或直方图；两种机制仍消耗同一固定成本。

候选配置保留原方案的全局最终顺序：后续交付等待前序最终确认，取消形成的 WITHHELD 也进入同一最终序列。控制响应不等待计算批次或交付确认。慢接收者可能阻塞后续结果，已准入票据可能在排队时过期；不能因此续期、重采样或退款。仅按接收路由排序的较弱配置作为对照，不替代这一要求。

轮询只返回登记状态及既有公开事件，不显示私有就绪、进度或内部异常；控制确认仅表示命令已应用。永久丢包在有限观察窗口末尾保持 ACTIVE，不伪造 CLOSED 或成功。完整观察同时包含原始传输事件，不能只检查缓冲后的应用顺序。

运行 `python3 outputs/agent-cryptography-design-20261025/public_transcript_model.py` 和 `python3 outputs/agent-cryptography-design-20261025/test_public_transcript.py`。当前 **17 项语义测试通过**；K=1 的 240 个严格顺序配置及 240 个较弱对照配置，对 9 个输入的 24 个有向增删邻接执行 **11,520 次完整分布比较**，枚举 43,560 条执行路径。两次查询的检验界为乘数 4、δ=1/2，最大观察损失为 7/16；这些是玩具参数，不能当作生产隐私参数。另有 K=2 的局部检查及 K=40 的公开工作步数检查。

四个反例在统计输出固定为零时，分别通过私有就绪状态、跳过空记录、私有失败和私有丢包泄露差异。这说明统一错误文案与结果去重不足以保证完整观察隐私。两次条件机制的基本组合依据 [Dwork–Roth 附录 B.1](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf#page=271)；将部署轨迹归约到该条件仍须证明。

`public_transcript_contract.json` 列出七项实现对应条件。下述新配置已实现 OBS-2 的发布资格与 L3 原子决定；扩展配置进一步实现 OBS-3 的内部跨路由最终前缀和发送准备限制。后续公开网关配置已提供五类认证请求及签名最终分页，但全部错误、可用性和物理观察映射仍未完成。协议模型与这一事务组件都不能单独证明现有网络实现满足完整公开观察隐私。

## 原子发布与交付准入

`atomic_publication.py` 提供新的 `AtomicPublicationSender` 和认证见证版本。在首次操作登记前，将授权根的保护域和接收者绑定到不可变路由及有效期。每个调度发布槽在同一事务内保存 WITHHELD，或同时创建 ADMITTED 决定、原交付票据、稳定请求标识和 outbox；如果该槽同时完成计算，结果与全部费用也在这次提交中。整组状态先进入见证镜像，再本地提交。

新配置禁止独立调用 `admit_v2` 创建第二次领取。既有发送端只将内部准入代码抽出为需要已开启守卫事务的 `_admit_v2_tx`，其原接口仍保留授权、期限和重试检查。取消前后仍按原 L1 边界分别退款或不退款；路由撤销导致明确 WITHHELD。未知内部或存储错误使业务事务回滚，不被包装成正常 WITHHELD；其外部观察处理仍待网关完成。

运行 `python3 outputs/agent-cryptography-design-20261025/prototype/test_atomic_publication.py`。**16 项测试通过**，覆盖八个 ADMITTED 和两个 WITHHELD 的实际进程退出点、见证确认丢失后的精确恢复、双机制同次最终提交、过期与撤销、票据/决定覆盖审计，以及本机认证见证上的提交和新副本恢复。认证见证测试记录 205 次请求、TLSv1.2；它不是新增公开网关或跨主机测试。受共享准入核心调整影响的发送端、接收端、归档、P2 和贡献交付五组测试均重新通过，分别为 25、28、19、8、10 项。

## 跨路由最终顺序

`ordered_publication.py` 提供 `OrderedPublicationSender` 和认证见证版本。它继承原子发布，并按租户与保护域保存 `final_events`：从序号 1 开始，每一项必须是明确 WITHHELD，或拥有已验证的 ACCEPTED/CLOSED 凭据。最大连续事件序号就是最终水位 F。新结果或首次终止报文只允许为 F+1 准备，检查发生在守卫事务内、读取私有结果之前，因此第二条路由不能绕过第一条路由尚未完成的交付。

接收确认、路由确认前缀、全局最终事件及连续 WITHHELD 的推进在同一次见证事务内提交。前导 WITHHELD 则在原发布事务中推进。确认丢失时保持阻塞；票据过期不会虚构 CLOSED，也不延长有效期或退款。排队期间已过期的后续票据只能在轮到自己后走原有终止确认。公开控制事务仍能执行，不相交保护域使用独立前缀。

运行 `python3 outputs/agent-cryptography-design-20261025/prototype/test_ordered_publication.py`。测试包括双路由混合机制、ACK 丢失和重试、过期后 ACCEPTED/CLOSED 分流、取消事件排序、并发确认与准备、独立域、伪造/缺失前缀恢复拒绝及实际进程退出。认证网络场景使用两个接收服务和三个见证服务，验证第一次 ACK 的真实连接丢失后第二路由保持阻塞，再依次交付直方图与计数。准确测试数量、请求计数和故障点以 `ordered_publication_test_results.json` 为准；契约见 `ordered_publication_contract.json`。

这一层保证新结果准备及规范最终事件的顺序，不承诺已发送重复包在网络上的总到达顺序。单独的顺序组件中，`final_events` 仍是内部记录；下述网关扩展已提供认证读取和精确响应重试，完整安全响应映射仍待完成。直接调用基类、任意 Python 或数据库访问仍在可信边界内；当前实现不是进程隔离。保留完整历史，未引入新的存储容量或生产级安全保证。

## 认证公开网关与请求日志

`public_gateway.py`、`public_gateway_transport.py` 提供新建配置 `PublicGatewayLedger` / `TLSPublicGatewayLedger` 和实际本机双向 TLS 服务。请求单独签名，绑定部署、租户、保护域、调用者、密钥、请求编号及创建时限；可信管理员预先固定证书与方法权限。响应使用独立签名域并绑定完整请求摘要。客户端发送应用数据前核对服务器证书，收到响应后使用预先固定的密钥验证签名。

| 公开方法 | 返回或效果 |
|---|---|
| CHALLENGE | 为原有动作证明创建并持久保存挑战 |
| SUBMIT | 验证动作、委托链与挑战，登记操作及共享预算，返回 RECORDED |
| CONTROL | 取消、根撤销、暂停或恢复；确认控制已应用，不推进私有计算 |
| POLL | 仅返回本调用者操作的已发布决定和最终状态，不读私有进度或结果 |
| FINAL | 有保护域观察权限的调用者读取最多 16 条连续最终事件，响应签名绑定请求 |

请求效果、证明使用、控制记录、原签名响应和日志在同一次见证事务中提交。相同租户、密钥和请求编号只能绑定原始请求；重复请求返回原响应字节，不重复消耗证明或执行动作。精确重试可以超过原请求创建时限，但仍须通过当前密钥、登记权限与证书认证；撤销会阻止缓存响应读取。最终分页游标由客户端携带，同一分页请求重试保持原页面，不随后来状态变化。

暂停状态持久保存；可信调度器只执行 noop 工作推进，控制必须经过公开请求。取消直接使用必要的操作元数据，不解密私有结果。恢复审计要求动作、挑战、证明和非 noop 控制均有日志覆盖，并核对暂停状态、签名响应与连续最终分页；旧副本不能越过新权威状态返回缓存。

运行 `python3 outputs/agent-cryptography-design-20261025/prototype/test_public_gateway.py`。**23 项测试通过**，包含 64 个签名字节变异、九个实际进程中断点、并发重复请求、权限/请求冲突、控制退款边界、原响应精确恢复和多种伪造/缺失日志拒绝。认证网络流程完成实际提交响应丢失后的重试、计算前后相同轮询、取消、完整直方图结果交付及签名最终查询：公开请求 11 次、发送见证 916 次、接收见证 4 次、结果交付 1 次，观察 TLSv1.2；另验证一次错误服务器证书固定值拒绝。所有服务共享本机与 CA，身份、密钥和数据均为合成测试材料。

## 用户贡献预处理

`contribution_ingestion.py` 提供独立的新建配置 `ContributionLedger`。可信管理员在参与数据进入前固定 N 个稳定用户标识；无记录的用户仍保留其槽位。每条记录带有上游可信分类器给出的桶编号，0 表示不满足条件。同一用户的任意多条记录按公开目录顺序选择最小正编号，重复或重排记录不改变结果。计数取该槽是否非零，因此计数与直方图来自同一裁剪规则。

删除一个用户的全部记录时，其他槽位不变；计数最多变化 1，直方图最多有一个坐标变化 1。这一论证以固定用户映射、固定目录、可信分类及增删邻接为前提。替换已有用户的记录可能改变两个桶。分别发布计数与直方图仍是两次收费的机制，不能把联合输出按一次成本发布。

新配置将加密计数快照、加密直方图快照、目录绑定和批次来源在一次见证事务中写入，拒绝普通直接快照导入。签名动作引用不可变快照；准入只检查来源元数据，不在 L1 前读取私有槽位。相同租户内的同一 lineage 不能绑定新域，快照更新也不创建预算。管理员仍可伪造新 lineage，真实身份去重与跨租户群体重叠需外部可信管理。

运行 `python3 outputs/agent-cryptography-design-20261025/prototype/test_contribution_ingestion.py`。当前 **19 项测试通过**：512 个用户桶子集组合、1,536 次删除用户检查，重复/顺序不变性、两个并发导入争用、签名混合机制共享预算、来源拒绝与恢复审计，以及六个实际子进程退出点。65535 槽和 64 桶仅验证编译器容量边界。结果见 `contribution_ingestion_test_results.json`，详细契约见 `contribution_ingestion_contract.json`。

这一配置没有公开导入端点，导入错误、时长和成功与否必须留在可信边界；统一错误字符串不等于观察隐私。当前也没有真实身份解析、原始数据分类器或全局血缘管理。贡献导入与 retention-v2 网络交付的组合验证见下节；以上测试不构成完整用户级端到端 DP 证明。

## 从贡献裁剪到认证交付的组合验证

## 已实现和验证的范围

- 两个账户的全有或全无预留，以及账户汇总与逐操作消费的独立核对。
- 同一操作的重试、参数替换拒绝、跨租户命名空间隔离。
- RESERVED 取消退款，STARTED 取消核销，并拒绝晚到提交。
- 恢复保留原种子，递增执行世代号，拒绝旧执行器。
- 输出与消费在同一数据库事务提交，已提交输出不能替换。
- 分离 L3 交付准入与发送；撤销前的在途交付可以完成，撤销后的新准入失败。
- 8 个独立数据库连接同时抢占两个单位的额度，只有两个操作获准。
- 8 个连接重复提交同一 ID，只产生一次额度占用。
- 十一个持久化边界的实际子进程退出，重新打开数据库后验证回滚或完整提交。
- 交付票据绑定网关、会话和接收者，最长有效期 60 秒且不超过根授权到期；原票据重试不能续期。
- 公开新请求与可信网关恢复分开，撤销后不能把旧票据传入新请求绕过授权。
- 可信服务时钟在已保留数据库状态上检测回退；过期请求即使被拒绝，也持久保存已观察时刻。

十一个崩溃点是：预留提交前后、Claim 提交前后、结果写入后但计费前、完整结果事务提交前后、交付票据提交前后、传输交接准入记录提交前后。使用 `os._exit` 模拟进程死亡；不代表验证了断电、磁盘损坏、文件系统缓存故障或跨节点故障切换。

## 必须保持的信任边界

`reserve` 的动作与成本来自模拟的可信验证器；`claim`、`recover`、`commit` 来自模拟的可信执行服务。actor、recipient、gateway、session 字符串仅作为测试身份，并不是身份认证凭证。基础 Ledger 内核没有签名验证、真实委托链、机制注册表、完整策略语言或密钥管理。新增 DPLedger 只固定登记一个候选机制，不是可动态注册任意机制的生产服务。

基础内核动作采用内部 JSON；签名入口另行固定规范 CBOR/COSE 字节。基础、双维、调度及签名测试配置仍使用明文合成状态；下述 EncryptedLedger 单独覆盖敏感字段加密。所有配置均不得放入真实数据。基础 Ledger 不计算 DP 噪声；DPLedger 调用固定工作量计数参考内核，使用持久种子的前 80 比特。理想独立均匀比特下的隐私界由单独精确概率检查支持；OS 随机源、机器恒时性和真实输入管线未获验证。

`admit_delivery`、`recover_delivery` 与 `emit` 是内部原语，不是公开 HTTP fetch。新请求即使使用历史 delivery_id，也必须检查当前授权。只有可信网关使用 `recover_delivery` 恢复原已准入发送；不能换会话、续期或改变接收者。过期后要再次领取，必须走当前授权下的新准入。生产部署仍需实现真实的网关和会话认证。

`handoff_admitted` 只表示根据事务中采样的服务时钟批准交给传输层，不证明实际发送或接收，更不是网络到达截止时间。时钟回退检测不能抵抗数据库旧快照恢复或管理员改写时钟和数据库。事务失败时保留时钟下界、回滚业务写入，由事务内保存点实现。

基础 Ledger 没有顺序发布控制器；新增 ScheduledLedger 提供持久逻辑控制器和内部发布资格，但不实现外部网络顺序。按顺序分配序号或按顺序批准发送，不代表字节在多连接上一定按顺序到达。不能向 Agent 直接暴露本内核的 NOT_COMMITTED、内部就绪状态、私有计算进度或恢复状态。

观察模型给出了两类反例：输出恒定为零时，READY/PENDING 仍能泄露私有完成差异；结果 A、B 始终按序输出时，一个无关控制确认相对结果的先后仍可能泄露信息。只隐藏时间戳不足以消除这种应用层泄露。

在 9 种隐藏完成调度和 4 种固定公开控制调度中，玩具模型把所有控制响应延后到批次完成屏障后，可使完整终止轨迹一致。这是有限范围的充分限制，牺牲响应能力，不替代原目标中的动态并发、即时撤销及失败恢复设计；这些组合仍需证明。

## 双维账户与计数集成

`dp_ledger.py` 在同一 SQLite 事务中将授权根、保护域、机制配置和两个必扣账户绑定。固定 K=40，每次登记成本为 epsilon 700000 个百万分之一单位，以及 delta 8388608 个 2^-64 单位。每维限额最多为 2^62 个内部整数单位；本原型不支持配置迁移或历史预算重置。

网关登记方法 `reserve_count` 不接受调用方自报成本。即便误调用内部 `reserve`，配置校验也会在事务内拒绝漏项、改价、跨域账户和机制降级。新授权根和新快照沿用已有保护域账户；保护域的真实血缘归并仍由可信管理员负责，不能抵抗管理员把同一人群恶意拆成多个域。

登记回执只返回 operation_id、action_digest 和固定 REGISTERED 标记；操作未开始、已开始、已提交时，重试的回执相同，不包含种子、输出或内部就绪状态。完整内部行仅供可信执行器使用。类型绑定不是对任意本地 Python 调用、数据库修改或恶意管理员的权限隔离。

可信执行器在 STARTED 后读取已固定的合成快照，以原种子前 80 比特计算噪声，输出为八字节大端整数。恢复世代号不参与噪声计算。结果与两维消费原子提交；登记回执或执行完成摘要都不是 L3 领取许可。旧的交付票据规则继续适用。

新增 17 项集成测试全部通过，包含 9 个实际进程死亡场景：第一维预留后、预留事务提交前后、Claim 提交前后、结果写入后、第一维结算后、结果事务提交前后。精确重试、双维不足、共享域并发、取消退款/核销、同种子恢复和不泄露内部状态均被检查。`dp_test_results.json` 保存证据及源码摘要。

DPLedger 接通账户、内核和内部领取路径。ScheduledLedger 进一步接通持久逻辑推进、数据库结果提交与发布资格；仍未与真实时间和对外网络形成同一条已证明的观察轨迹。

## 持久逻辑控制器

`scheduled_ledger.py` 为每个保护域保存调度时隙、轮转位置、任务准入序号、私有计算累加器、幂等推进请求和有序事件记录。任务与双维预约在同一事务登记，避免预约成功但任务丢失。一次 `advance` 先记录公共控制确认，再执行一个逻辑步骤，最后检查按序发布；结果、双维消费和发布记录在同一事务保存。

`expected_tick` 防止两个驱动者同时推进，request_id 使提交后丢失回复的重试不重复执行。原始 claim/commit/cancel/revoke 路径在此配置下被拒绝，控制必须经过调度器。这里只约束可信代码的 API 使用，不能抵抗本地代码绕过类方法或直接写 SQL。

支持动态加入任务、公开暂停、撤销、到期和取消。取消任务仍消耗剩余公开逻辑槽位；开始前取消归还两维额度，开始后取消核销。发布 RELEASE 只表示内部可领取资格；新 L3 必须同时检查该资格、当前根授权和接收者。已有 L3 票据仍可在有限期内由原网关与会话恢复。事件读取方法仅供内部使用，没有开放原始日志给未认证调用方。

19 项测试通过，包含 10 个真实子进程退出切点：任务登记前后、控制写入后、计算准入后、步骤写入后、结果写入后、第一维结算后、发布写入后、时隙事务提交前后。四种二元合成输入在同一非自适应控制计划下生成相同逻辑事件记录；这不代表已经穷举真实部署的联合 DP 分布。报告为 `scheduled_test_results.json`。

逻辑时隙不是墙钟时间。每一步仍执行 Python 与 SQLite 操作，可能有不同的运行耗时；控制确认只保证属于当前逻辑时隙，不承诺物理响应时延。当前一个数据库事务执行一个任务步骤，尚未验证多机执行、磁盘故障、真实网络顺序、错误响应策略或性能。只使用新建临时数据库和合成数据。

调度准入现有独立的公开步骤：pc=0 的事务只持久化 STARTED 和种子，不读取私有快照或噪声位；从下一事务的 pc=1 开始执行 N+81 步内核，故总工作量为 N+82。取消任务仍走同样固定槽位。新增测试在私有读取回调中通过另一连接确认种子已经提交，并验证准入事务失败时没有私有读取。旧 N+81 调度记录不会被静默重解释，工作量配置不符即拒绝；不提供旧库迁移。原数学内核及精确概率模型的 N+81 不变，模型不是这个新增持久步骤或见证网络的完整隐私证明。

## 签名准入与严格编码

`wire.py` 与 `signed_ledger.py` 实现 `count-direct-v1`：仅覆盖当前固定计数机制的直接根授权入口，不替代完整 Action、Grant、Delegation、Permit 和 Receipt 协议。身份公钥由模拟可信管理员登记；同一租户中禁止把相同公钥登记成不同角色或不同主体；真正验证的是 Ed25519 密钥持有及登记角色，尚未接入工作负载证明或 TLS 身份。多跳计数委托由下述 DelegatedLedger 子配置另行实现。

编码固定采用 RFC 8949 §4.2.1 的字节序确定性规则，COSE_Sign1 强制 tag 18、受保护头 `{1:-19,4:kid}`、空未保护头和内嵌 payload。算法 -19 是 RFC 9864 的明确 Ed25519 标识。external_aad 同时绑定协议名、版本、CountActionProof 类型与算法套件。禁用浮点、布尔、null、非确定长度、重复键、未知字段、其他 tag 和尾随数据；限制 64 KiB、深度 8、容器项数 128。

`count_direct_v1.cddl` 给出闭合字段表，运行时还有时间窗口、成本、角色和账户绑定检查。该 CDDL 尚未通过独立 CDDL 工具验证。`wire_vectors.json` 固定保存动作字节、受保护头、AAD、Sig_structure、签名及完整封包。文件中的私钥是 RFC 8032 公开测试种子，不能用于部署；这些 COSE 向量尚未完成独立实现互通检查。

一次性挑战绑定租户、公钥、服务和期限。验签、当前授权检查、挑战消费、已接受证明存档、完整动作字节绑定、预算预留与任务登记同事务完成。提交前失败可重试同挑战；提交后证明不可重放，丢失回复必须取得新挑战、用新 proof_id 签署相同动作。即使仅改变内部 JSON 未包含的 deadline，也会触发永久动作冲突。签名 ACK 的 action_digest 指线缆 CBOR 的 SHA-256，内部 JSON 摘要仅用于既有账本实现。

计算准入和新 L3 重新检查动作期限、密钥登记状态和根授权；新票据同时受动作期限及密钥到期限制。撤销前已完成 L3 的原票据仍可在原有限期内恢复。已接受证明保存原始签名，可在密钥后来撤销后重新验证历史签名，不把现在的撤销状态误当成过去签名无效。

新增 23 项测试通过，包含 RFC 8032 已知答案、固定字节向量、65536 个两字节解析输入、64 个签名字节篡改、角色及上下文错配、8 连接重放竞争和 3 个真实进程死亡场景。报告 `signed_test_results.json` 记录环境中的 cryptography 49.0.0。原始签名计算使用该库；自定义受限 CBOR 解析器尚未经安全审计，不能把测试通过当作完整解析器证明。

## 多跳计数委托

`delegated_ledger.py` 实现 count-delegated-v1 动作与 count-chain-v1 凭证。最多八个凭证，总长不超过 64 KiB。根密钥由可信管理员按 tenant/root 固定，不能从提交的链中自行认领信任；Grant 与 Delegation 使用不同签名域。父摘要、叶摘要均绑定完整确定性 COSE 字节。

每个子签发者及密钥必须等于父 subject，深度递增，时间窗、集合范围、最大深度和累计额度只能缩小。数据域与原账户不允许替换，空集合表示拒绝。动作绑定叶摘要、叶身份、公钥、公开快照、接收者与机制；当前只执行固定计数，不开放任意谓词或跨域查询。

每个操作同时占用全局 epsilon/delta 与每个祖先的 epsilon/delta 累计上限。两级委托的三份凭证共形成八条费用约束，不能将其相加解释为新增隐私预算。取消、核销和结果提交沿用同一多账户事务。分叉新子凭证不能绕过父额度；相同凭证 ID 的内容不可重签替换，历史消费不会因重新登记而清零。

根记录持久固定 direct/delegated 授权模式；直接入口不能为 delegated 根登记动作或创建新 L3。已有操作的根不能切换模式。所有祖先凭证与密钥在预约、L1、发布及新 L3 检查，票据有效期也受祖先期限约束。未使用过的凭证同样可以通过独立撤销记录预先撤销。历史审计验证签名与链结构，不因后来撤销而抹去既有事实。

新增 22 项测试通过，覆盖两级委托、根信任伪造、兄弟父链拼接、权限扩大、时间与深度、账户替换、空权限集、叶绑定、父预算分叉、8 连接共享上限竞争、祖先撤销与到期、直接入口降级绕过，以及三个实际进程死亡切点。受限 CDDL 和固定链向量分别保存在 `count_delegated_v1.cddl`、`delegation_vectors.json`；报告为 `delegated_test_results.json`。

这些是合成输入上的计数子配置。密钥登记、授权根建立、撤销管理及调度控制仍是可信管理调用；没有真实工作负载身份、签名代理隔离、其余对象族、独立协议互通、实际网络观察证明或生产密钥保管。自定义解析器与策略实现仍需安全审查。仅支持新建测试数据库，不提供旧版迁移。

## 敏感状态加密与完整性故障

`encrypted_ledger.py` 将 StateVault 接到多跳签名计数流程，保护四类状态：固定容量的快照、32 字节操作种子、8 字节结果，以及计数/噪声中间状态。加密发生在 SQL 写入之前，未采用先明文写库再替换的方法。快照每个槽位编码为一个 0/1 字节；中间状态为固定八字节 `>I4B`，旧明文计数列始终保留公开默认值。公开 ID、授权链、预算、队列与时隙元数据不隐藏。

实现使用 cryptography 49.0.0 的 AES-256-GCM-SIV 和 HKDF-SHA256。可信启动方从数据库外注入 32 字节主密钥和 16 字节部署 ID；用途标签分别派生加密、结果绑定和密钥校验子密钥。本版只接受版本 1，不提供在线轮换、KMS/HSM 或 Python 内存清除。测试中的密钥全部是公开合成夹具，不能用于部署。

密文格式为 `ACV1 || uint32be(1) || nonce[12] || ciphertext || tag[16]`，上限为 65536 字节明文。AAD 绑定协议、版本、部署 ID、字段类型和记录身份。种子/结果绑定租户、操作 ID 与不可变内部动作摘要；快照绑定租户、域和快照 ID；中间状态额外绑定域、队列序号、工作量和 pc。这个 pc 绑定能拒绝把旧中间密文放到较新步骤，不能阻止整个账本一起回退。完整格式见 `storage_contract.json`。

低熵结果不再保存裸 SHA-256，改用用途隔离的 HMAC-SHA256，同时绑定操作上下文。交付票据保存相同的带键绑定值；解密后重新验证。它是内部结果关联标识，不是公开可验证签名，也不替代 ActionProof 或 L3 授权。

数据库记录存储配置和启动密钥校验值；连接时及每次事务前检查。明文服务拒绝打开加密配置，错误密钥或部署 ID 同样拒绝。已有明文库不会自动转成加密库，也不能声称旧明文页面、日志和备份被擦除。所有测试只创建新库。

密文头、nonce、标签或上下文不匹配时产生内部 STORAGE_INTEGRITY，业务事务回滚；不把故障当成空快照、可退款取消或抽取新种子的理由。已持久化 STARTED 的预算继续占用。恢复需可信操作员恢复同一合法状态，或按原策略核销；目前没有自动修复流程。错误不能直接暴露为新的公开私有状态查询接口。

19 项测试通过，含 RFC 8452 两个 AES-256 已知答案、全部 68 个种子封包字节翻转及截断、跨字段/租户/操作/部署替换、旧步骤密文重放、错误密钥、入口降级、结果绑定篡改、并发重复推进，以及取消与撤销。四个真实进程死亡切点覆盖计算准入写入后、时隙提交前、结果写入后、时隙提交后。检查热回滚日志及 WAL 中不出现指定合成长种子/主密钥/快照，并验证恢复后种子、结果和账户一致；这不是对短计数值、内存、交换文件或所有存储介质的完整取证证明。证据保存在 `encrypted_test_results.json`。

AES-GCM-SIV 的 nonce 误用抵抗不意味着可以主动复用 nonce，也不提供防回滚。重复 nonce 与相同明文/上下文会泄露相等性。当前方案仍要求可信完整账本、可信执行器及高熵密钥；只能增加私有字段落盘保护，不能防止恶意管理员重写消费、删除状态、整库恢复，或已被攻陷的执行器读取内存。物理运行时间、访问模式、备份治理、生产密钥轮换和完整观察证明仍开放。原语参考 [RFC 8452](https://www.rfc-editor.org/rfc/rfc8452)、[RFC 5869](https://www.rfc-editor.org/rfc/rfc5869) 与 [cryptography AEAD 文档](https://cryptography.io/en/49.0.0/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCMSIV)。

## 独立见证与本地账本回滚恢复

`witnessed_ledger.py` 实现 WitnessedLedger 与 ReferenceWitness。后者是独立本地 SQLite 见证模拟器，假设其状态线性化、持久、不会回滚或伪造；它不是已部署的认证远程服务，也不具备硬件不可回滚保证。见证命名空间由可信启动方固定的部署 ID 决定，不能由 Agent 指定。见证不存在或不可用时拒绝准入，不能自动从本地旧余额建立新历史。

每次业务事务先核对本地 `(seq,digest)`、完整状态摘要和见证当前头。执行暂存变化后，生成完整逻辑状态镜像：表结构与所有表行均覆盖，包括预算、根与委托撤销、已使用证明、时钟下界、加密种子/快照/中间态/结果、调度请求、发布资格和交付票据。仅本地 `witness_anchor` 排除在镜像外。见证只保存私有字段密文，不获得存储主密钥。

见证以旧 seq/digest 为条件原子保存新镜像及请求记录，然后本地更新 anchor 并提交，最后才返回成功或结果。见证 CAS 是该配置的权威状态提交点，本地数据库是可恢复的副本。见证提交前失败可放弃暂存事务；见证确认后本地失败不能退款或撤销见证，必须从见证恢复。读取私有数据发生在独立 L1 已经通过见证并在本地提交之后。

每次 CAS 使用独立随机请求 ID。只有同一 ID、相同旧版本和完全相同新镜像可作为传输重试，返回原确认；不同请求即使镜像恰好相同也不能借旧确认跳过版本比较。相同 ID 改写内容被拒绝。两个克隆副本即使都通过开始时检查，也只有一个不同请求能用同一旧版本提交。这里的去重只是见证提交去重，不是新的公开 fetch 许可。

恢复只接受见证当前镜像，在一个本地事务中重新安装数据，复核既有表结构、完整镜像摘要、外键、签名链、私有字段认证和账户审计，再更新 anchor。不会执行快照中携带的 SQL，也不会重新计算噪声、领取结果或重建额度。恢复期间观察到见证前进则回滚并重试；恢复返回后见证仍可能继续前进，因此每次后续业务事务都要再次检查和 CAS。丢失全部本地文件可用 `restore_new` 创建相同受信模式的空壳再恢复，不能用普通 `create` 重置已有命名空间。

19 项测试通过，包含 7 个真实进程死亡场景：见证接受前后、本地 anchor 写入后、本地时隙提交后，以及恢复删表行后、恢复提交前后。另覆盖确认丢失、错误确认、最终结果只存在于见证时的恢复、旧副本和两克隆竞争、撤销/证明墓碑/时钟下界恢复、已有票据与交接记录、损坏镜像和结构不兼容、见证不可用、无见证入口降级及恢复竞态。报告为 `witnessed_test_results.json`，契约为 `recovery_contract.json`。

两个负面对照保留在测试中：只恢复旧的加密账本能使同一操作产生两个不同输出、每份账本却只记一次费用；同时恢复本地库与模拟见证库，协议仍无法发现回滚。这明确限定了本轮证据：防护针对本地副本回滚，依赖见证的不回滚与认证假设。

每次事务完整复制和散列镜像，最大 16 MiB，当前参考实现持有本地事务锁调用见证。下述适配器已接通本机 mTLS、固定见证身份、新鲜响应及写权限，但仍沿用全量复制与持锁方式。生产设计还需复制日志/不可变密文的可靠可用性、身份生命周期、独立故障域、有界服务资源、单写者 fencing 与不长期持锁的提交架构。只有摘要而无恢复数据，最多发现回滚后冻结，不能实现本原型的精确恢复。数据库原子提交和备份接口的背景分别见 [SQLite 原子提交](https://www.sqlite.org/atomiccommit.html) 与 [Backup API](https://www.sqlite.org/backup.html)；它们本身不提供这里假设的外部不可回滚历史。

## 见证连接认证、响应新鲜性与写权限

`witness_transport.py` 增加 `TLSWitnessClient`、`WitnessTLSService` 与 `TLSWitnessedLedger`。服务只在 `127.0.0.1` 的临时端口监听，测试结束后关闭。可信启动方固定 CA、服务主机名、客户端证书和私钥、见证 Ed25519 公钥及 kid；证书信任不从对端声明自动建立。TLS 双向验证证书，客户端另校验服务主机名。测试证书和密钥临时生成，私钥文件权限为 0600，随临时目录清理。

认证主体是已通过 TLS 验证的叶证书 DER 的 SHA-256 指纹。每个部署分别登记 admin、writer、restorer 或 observer：admin 可首次初始化；writer 可 CAS；restorer 可读恢复镜像；observer 只能读头。admin/writer/restorer 也可读头，admin/writer 可读镜像。有效 CA 证书本身不授予任何部署权限。授权登记和撤销目前仅为可信离线管理调用，没有开放管理 RPC，也没有自动证书轮换或 CA 撤销生命周期。

写权限及当前撤销状态与 CAS 在同一个见证写事务中检查，并先于历史重试记录查询。连接建立后发生的撤销不会因为旧连接或旧请求 ID 被跳过。若某写事务已先取得权限快照和写锁，它可以先于后来的撤销完成；本协议不追溯撤回已有输出。读权限和头/镜像读取也共享一个读事务。

每次请求使用新的 32 字节随机挑战；CAS 精确重试保留原请求 ID、旧头和镜像，但更换挑战。响应使用独立签名域 WitnessResponse 的 Ed25519 COSE_Sign1，同时绑定协议、服务、方法、部署、本次挑战、完整请求元数据摘要、TLS 请求者指纹、状态、结果以及回复正文长度和摘要。客户端固定验签公钥与 kid，拒绝旧响应、跨请求者/部署/方法替换及正文损坏。新挑战约束了本次响应的来源；不能阻止受攻陷的见证对旧头重新签名，因此诚实见证与不可回滚前提仍保留。

帧为 `WRP1 || uint32be(metadata_length) || uint32be(body_length) || metadata || body`。元数据最多 8 KiB，正文最多 16 MiB，读取正文前检查长度；每个连接只处理一个请求。元数据采用现有受限确定性 CBOR，响应元数据是强制 tag 18 的 COSE 封包。镜像正文独立于 CBOR 64 KiB 对象限制，并由请求/回复签名中的摘要绑定；见证把镜像当作有界不透明字节，安装恢复时才验证完整结构与账本内容。字段契约见 `witness_rpc_v1.cddl` 和 `witness_transport_contract.json`。CDDL 尚未独立验证。

客户端为连接、握手、发送和读取设置同一个单调时钟截止时间。超时不是服务器取消：数据库锁等待或已开始的 CAS 可能在客户端放弃后完成。回复丢失、超时、签名损坏均不能证明见证没有提交。旧本地副本必须重新查询可信当前头并恢复已接受状态，不退款、不重新生成种子。认证配置拒绝普通见证适配器和明文降级；这里约束的是受信应用路径，不防止有本地代码执行权的攻击者修改 Python 对象或直接写库。

新增 19 项测试全部通过，共记录 332 次真实回环网络调用，覆盖缺失/过期/非受信客户端证书、错误服务主机名/CA/签名公钥、有效证书但无权限、跨部署访问、只读角色、撤销与 CAS 同事务竞态、撤销后的旧请求重试、挑战重放、签名域/上下文/正文篡改、严格字段和帧大小，以及完整计数账本的丢失回复、超时和损坏回复后恢复。该套件没有新增实际进程死亡测试；原见证恢复套件的七个死亡切点另行保留。报告为 `witness_transport_test_results.json`。

当前运行环境实际协商 TLSv1.2，Python 3.9.6 的标准库 SSL 链接 LibreSSL 2.8.3；没有把它记作 TLSv1.3 或生产环境验收。配置显式要求证书验证和主机名核对，相关 API 语义见 [Python 3.9 SSL 文档](https://docs.python.org/3.9/library/ssl.html)，测试证书生成接口见 [cryptography 49.0.0 X.509 文档](https://cryptography.io/en/49.0.0/x509/tutorial/)。帧长和网络等待已有上限，但线程总量、请求速率、数据库执行时间和总服务资源尚无完整上限。仍需受支持的生产 TLS 环境、CA/密钥生命周期、独立不可回滚见证部署、复制可用性、短持锁提交架构、负载评估，以及完整网络观察证明。该适配器只负责见证 RPC；下节另外接通固定计数结果的认证推送，完整公开发布协议仍未完成。

## 认证结果交付、持久发送队列与接收端去重

`delivery_transport.py` 新增 `DeliveryLedger`、`DeliverySender`、`RecipientInbox` 与 `RecipientTLSService`，存储配置为 `mtls-count-delivery-outbox-v1`。它继续使用认证见证与全部既有计数、签名委托、加密和 L1/L2/L3 规则。可信驱动者只为已获 RELEASE 资格的结果调用 L3，再推送原结果；没有给未受信调用方开放 fetch、就绪状态或原始内部错误接口。协议字段见 `count_delivery_v1.cddl`，完整契约见 `delivery_transport_contract.json`。

可信管理方固定 `(tenant, recipient, gateway, session)` 路由，登记双方 TLS 证书指纹、应用签名公钥和 kid，登记后不可替换。session 是可跨重连恢复的逻辑交付会话，不是 TLS 会话号。真实身份登记与密钥轮换尚未实现。连接使用双向 TLS；发送方先检查服务主机名和精确接收者证书指纹，才发送任何结果字节；接收方独立检查 TLS 客户端指纹与网关签名。

L3 通过后，在同一见证保护事务中创建票据和 QUEUED 发送记录；准入失败时两者均不生效。准备发送时检查原票据期限、当前路由状态、最早未确认序号、结果绑定和网关签名密钥，将 CountDelivery 签名封包加密保存为 READY，再允许网络发送。封包绑定部署、租户、双方身份与证书、逻辑会话、票据 ID、操作 ID、序号、原有效期和八字节结果。完整封包、确认及确认所对应的请求证据都先经 StateVault AEAD 再落盘，并纳入见证完整镜像。普通 emit 入口在此配置下拒绝。

接收端另用独立密钥和固定路由的 SQLite 收件库，原子检查时钟下界、原有效期、下一序号和重复记录。首次接收只插入一次加密封包，提交后才签署 CountDeliveryAck；同 ID 的重试必须封包字节完全一致。确认绑定本次新随机挑战、请求摘要、原封包摘要、票据和接收者证书，携带首次 accepted_at。发送方验证确认后才将队列置为 ACKED。两个签名对象使用不同 COSE external_aad；它们尚未经过独立实现互通。

发送断线、接收端已保存但 ACK 丢失、发送方收到 ACK 后退出，均只重发原封包，不运行机制、不新增费用或续期。网络成功无法替代本地确认提交，网络失败也不能推断接收端没有保存。若见证已保存 READY/ACKED 而本地提交失败，则恢复原权威状态。已确认任务再次驱动不再发送网络数据。

授权撤销阻止新的 L3，但原已准入票据仍可在原期限内恢复；路由撤销另阻止后续准备发送，不能召回已经在途的数据。接收端在首次收件事务中按采样时钟检查期限；accepted_at 不是实际提交或字节到达的墙钟期限；过期拒绝仍持久保存观察时刻，防止之后调低时钟重开有效期。已有合法 ACK 可在票据过期后归档，但不会因此获准再次传输结果。

顺序保证目前只覆盖固定路由：网关不越过未确认队首，接收端拒绝未见过的序号缺口。基础推送配置在队首过期后阻塞，不自动跳过或重置序号。下述终止扩展已经补上过期后不携带结果的原子确认/关闭；跨路由保护域发布、L3 前未交付事件及去重记录保留契约仍需完成。可信驱动仍不能把 QUEUED/READY 状态和错误直接作为公开查询结果；完整网络观察与物理时间隐私证明没有因此完成。

当前 25 项测试通过，实际建立 25 次交付网络调用；此外见证调用由既有认证适配器执行。8 个实际子进程死亡切点覆盖 L3 票据/队列提交前后、发送封包提交前后、接收端收件提交前后和发送端 ACK 提交前后。另覆盖六连接同时重传、失联重试、错误端点在结果发送前被拒、伪造/重放确认、路由错配、撤销、原有效期、接收端时钟回退、未发布任务、过期队首阻塞，以及完整见证恢复。报告 `delivery_transport_test_results.json` 保存当前源码摘要和环境版本。

ACK 表示配置中的接收者声明已持久保存，不证明恶意接收者诚实、用户已阅读或业务副作用只执行一次。去重依赖接收端保留不可回退的收件记录；此基础计数配置没有接收端见证；下述混合见证收件配置另提供有条件的本地回滚隔离和精确恢复，生产权威非回滚仍未验证。接收方收到结果后仍可按其权限使用副本。本机测试实际协商 TLSv1.2；没有 HPKE 中继端到端加密、生产 CA/签名密钥管理、有界总工作线程或负载验收。所有证书、密钥和输入均为临时或公开合成测试材料。

## 过期交付的终止确认与原子关闭

`delivery_terminal.py` 在独立的 `mtls-count-delivery-terminal-v1` 存储配置中扩展发送方和接收方，保留原始推送配置的行为。只支持新建数据库；旧配置不能解释新终止表，也没有自动迁移。协议字段在 `count_delivery_terminal_v1.cddl`，详细契约在 `delivery_terminal_contract.json`。此次扩展只处理已经通过 L3 的原票据，不替代 L3 前取消、WITHHELD 或跨接收者发布协议。

票据过期后，可信网关可为队首任务创建 CountDeliveryTerminal 签名控制对象。它绑定原部署、路由、双方证书、票据、操作、序号及原有效期；若曾准备发送封包，还绑定完整签名封包的 SHA-256，否则该字段为空。控制对象不包含计数结果或原结果封包；摘要也不是低熵原始计数的裸哈希。控制对象先加密落盘并经见证确认，再通过原双向认证连接发送，每次尝试使用新随机挑战。

接收端在与普通收件写入相同的 BEGIN IMMEDIATE 事务内检查原有效期、持久时钟下界和固定路由。若原封包已经保存，必须匹配封包摘要与全部票据元数据，返回 ACCEPTED 和原 accepted_at；若原关闭标记已经存在，只能返回同一关闭事实；否则只允许关闭当前下一序号，持久保存加密的 CLOSED 标记后才回复。不存在可用于推进队列的 ABSENT 或“查不到”响应。

这个共同事务是关键：若早先的收件事务已经在有效时间内通过检查，终止事务必须等其完成，再报告 ACCEPTED；如果关闭先提交，晚到的原结果、重签延长有效期或更换 ID 占用同序号都被拒绝。accepted_at 是收件事务内采样的可信时间，不能声称磁盘提交发生在票据过期之前。关闭标记和时钟下界也需要持久保存，不能因备份恢复而消失。

接收端以独立 CountDeliveryTerminalAck 签名域返回确认，绑定本次请求摘要、挑战、控制对象摘要、原封包摘要及 ACCEPTED/CLOSED 事实和首次事件时间。发送方验签后将请求和确认加密存入见证保护的终止表，再推进后续任务。原始 outbox 行保留 QUEUED/READY/ACKED 与原封包证据；新配置通过终止表派生有效 ACKED/CLOSED 状态，查询和队首选择不能只看旧 outbox.state。

关闭回复丢失后，只重发同一控制对象，保留首次 closed_at。接收端先收件、原 ACK 丢失且票据已过期时，同一协议返回原 ACCEPTED，不重传计数结果。见证已接受终止确认而本地未提交时，从见证恢复同一终态；相互矛盾的签名确认、改变首次事件时间或在 CLOSED 后追加相反的普通 ACK 都被拒绝，不能静默重写历史。

根或委托撤销后仍可核对原已准入票据的终态，因为该请求不重新释放结果；当前传输路由撤销、证书无效或接收端不可用仍会阻止请求，不启用降级身份。关闭不退款、不重新抽样、不创建新的 L3，也不延长原期限。只有收到并持久保存有效终态，发送方才认为该序号已解决。

23 项测试通过，包含 31 次终止/交付网络调用和 6 个实际进程退出切点：控制对象准备提交前后、接收端关闭提交前后、发送端终止确认提交前后。测试覆盖收件与关闭竞争、六连接重复关闭、回复丢失、原始 ACK 丢失后过期核对、未发送票据关闭后后续任务继续、提前关闭拒绝、元数据/签名/挑战篡改、空摘要与已有结果冲突、迟到结果和矛盾确认、权限撤销、旧配置拒绝及见证恢复。证据位于 `delivery_terminal_test_results.json`；原推送套件现有 25 项测试，已回归通过；新增检查修正路由密钥标识最多 32 字节，与共享 COSE 解析器一致，避免登记无法验签的路由。

不携带结果不等于不泄露信息：请求仍有路由、序号、时间和是否曾准备封包等元数据，回复明确区分已接收与已关闭。此接口只供可信驱动者使用，不能直接变成 Agent 的公开状态探针。整体保证仍依赖诚实接收端、不可回退的收件和关闭记录、可信时间以及生产身份与见证假设；跨路由完整观察证明、接收端灾难恢复、记录清理和有界服务资源仍未完成。

## 固定桶直方图内核与完整向量隐私检查

新增上一级 `histogram_kernel.py`、`histogram_model.py`、`histogram_results.json` 和 `histogram_contract.json`。独立可信内核和理想随机位下的精确检查已完成，并新增下述明文共享账本与持久调度。签名委托与祖先累计额度也已接入新的混合配置；加密向量状态也已在 EncryptedMixedLedger 中接入；混合见证已在下述配置接入，完整向量认证交付已由下述新配置接入，混合过期终止已由下述扩展接入，P2 直方图纵向验收仍开放。旧计数配置不会因新增这些文件而自动支持直方图。

输入为预先公开的 N 个槽位和有序 B 个桶：0 表示空位，1…B 表示一个用户被固定规则归入的单一桶。每个用户的全部记录必须先稳定去重，并按只依赖该用户和公共桶定义的规则归类；加入或删除一个用户不能重分其他用户的桶。桶集合、顺序、规则版本、容量和快照血缘需要可信登记，不能由私有总体规模、分位点或排序即时生成。这些预处理尚未实现。

每个桶使用独立的两个 K 位初始连续 1 计数之差加噪，再按公开 [0,N] 裁剪。每桶固定扫描全部 N 槽位、处理全部 2K 位和一次最终存储；总内核工作量为 B(N+2K+1)，不存在私有零桶的提前跳过。结果仅在全部桶完成后一次返回，按登记顺序编码成 8B 字节。各桶独立裁剪后总和可能超过 N，不据此公开真实用户总数或再作数据相关修正。B=1 的内核输出与现有计数一致。

在用户增删只改变一个桶的条件下，完整联合输出可以写为变化坐标分布乘以其余坐标的相同分布。其余因子的总概率为 1，因此完整向量的 hockey-stick 差值等于变化坐标的差值；裁剪是后处理。结合已有有界几何标量证明，得到整张直方图的 (ln 2, 2^(-(K+1))) 近似 DP，成本不乘 B。这里的有界噪声证明是本设计的推导；标准互斥桶敏感度背景见 [Dwork–Roth Example 3.2](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf#page=37)。有限支撑仍不能被记作纯 DP 或有限普通 RDP。

候选 K=40 时，需要 80B 个独立理想随机位，即完整 10B 字节随机带。代码显式请求全部随机字节，不把旧计数的 32 字节种子默认为任意长独立随机带，也不在桶间重复用前 80 位。秘密种子经 PRG 展开只能在另行明确的计算型隐私假设下解释。OS 随机源仍是工程假设，未因精确理想模型检查而获得审计。

新增 109264 个穷举内核执行、133 个完整联合分布对比、2360 个向量有向隐私不等式检查及 128 个标量方向检查全部通过。穷举范围明确记录为六组小型 B/K/N 配置，不能扩展称为所有生产执行穷举。另有 16 个 K=40 同随机带重放案例、5 个不同桶随机位布局案例（含 64 桶）和 9 个非法契约案例。固定逻辑访问位置由公开 pc 决定；这不是 Python 恒时性或完整网络轨迹证明。

负面对照在 K=2、N=5 时检出：跨桶共享噪声的联合差值为 3/8，替换用户为 81/256，同一用户多桶贡献为 71/256，均超过原声明的 1/8。有限 RDP 的反例事件仍为某一桶输出零，邻接分布概率分别为 1/8 和 0。可见只检查各桶边缘分布相似是不够的。

后续集成必须同时修改并验证七处契约：机制/桶目录与共享账户；动作及委托的桶顺序绑定；先持久 L1 后读取私有数据；完整随机带及私有中间向量加密；整个 8B 字节向量与费用的单次原子提交；认证向量封包和过期终止；见证精确恢复。持久步数 1+B(N+81) 已在合成明文账本及新的签名委托混合配置中实现；新的加密混合配置已支持这一接口，混合认证见证也已接入；完整向量认证结果交付已接入，混合过期终止交付已由下述扩展接入。一次计数和一次直方图必须在同一域账户上消费两次 (700000,8388608)，不能按桶或机制开新免费账户。具体变更和验收条件记录在 `histogram_contract.json`。

## 混合计数与直方图的共享账本及持久调度

## 混合状态的认证见证与精确恢复

`witnessed_mixed_ledger.py` 新增 `WitnessedMixedLedger` 和 `TLSWitnessedMixedLedger`，分别使用 `witnessed-signed-mixed-v1`、`mtls-witnessed-signed-mixed-v1` 独立存储配置。它们复用完整镜像协议并组合 EncryptedMixedLedger，无需复制另一套恢复算法。镜像包含新桶目录、快照目录绑定、签名证明、完整委托链与撤销、每一级预算、全部私有密文、调度进度、发布事件及内部交付记录，仅排除本地见证锚。

每次业务事务先核对见证当前头及本地完整镜像，事务暂存的新状态先经见证 CAS 接受，再更新本地锚、提交和返回。见证已接受而本地失败时，不把失败视作退款或重抽许可。恢复在一个本地事务中核对镜像摘要、受信结构、外键、存储配置、签名、账户及密文，并在提交前再次确认见证头没有变化。恢复不抽取新随机带、不推进逻辑任务或重复收费；直方图审计可能用已保存随机带确定性重放内核以核对结果，不能把它描述为完全没有计算。

认证配置复用现有 mTLS 和新鲜挑战绑定的签名回复；admin 初始化，writer 提交，restorer 只能取镜像，observer 不能取镜像。旧计数配置、无认证 ReferenceWitness、错见证签名密钥及已撤销证书权限均不能绕过新配置。认证仅验证本机回环链路，当前实际协商 TLSv1.2。

21 项测试通过，包含 1539 次服务端认证请求和 8 个真实进程退出场景。7 个参考见证场景覆盖接受前后、本地锚写入后、业务提交后和恢复删除/提交前后；另一个场景在真实 mTLS 的最终向量 CAS 已接受后杀死调用进程，恢复原完整结果、随机带和所有祖先费用。测试还覆盖旧副本隔离、两克隆同前驱竞争只有一个成功、回复丢失、私有中间向量恢复、撤销/证明/时钟下界恢复、已交付票据恢复、目录及账户篡改、镜像损坏和恢复期间见证前进。

含 N=65535 分类快照的镜像超过 CBOR 的 64 KiB 元数据对象上限，仍可通过独立 RPC 正文认证并精确恢复；正文总上限仍为 16 MiB。对镜像增长上限的测试通过降低公开测试阈值触发同一检查，证实拒绝时本地进度和见证头不变、原随机带及 HELD 费用保留。当前完整镜像复制、无界历史增长与持锁调用不能支持生产规模承诺；需要可扩展日志、历史保留规则和按公开容量判定的准入策略。

负面对照继续证明：若同时恢复见证与本地账本的完整旧副本，协议仍不能发现回滚。因此保障依赖独立、线性化、认证且不回滚的见证；本机 SQLite 模拟器不是这项生产保证。现阶段完成签名、加密、预算及恢复的混合路径，完整向量结果与终止交付已由下述独立配置接入。合同为 `witnessed_mixed_contract.json`，报告为 `witnessed_mixed_test_results.json`。

## 完整 v2 交付证据到终态承诺

`retention_delivery.py` 实现 `mixed-delivery-v2` 完整描述符、结果封包、无结果终止控制、双层签名请求和接收回执。描述符绑定上下文/派生 ID/序号、操作、原期限、动作摘要、域/快照、accountant、机制、N/B/K、编码及完整有序目录。结果必须完整为 8B 字节且每桶不超过 N；计数配置严格为一分量。描述符摘要由模块从规范完整字节重算，不接受一个外来摘要代替内容验证。

ACCEPTED 事实从完整验签的封包重建，CLOSED 事实从验签的终止控制重建；保存证据审计必须将整个事实重建后逐字节比较。终止查询只能复述同一已有事实，不能更换目录、原封包、首次事件时间或把空封包绑定解释成 ACCEPTED。普通交付回执、终止回执和后续 FINAL 查询对同一事件得到相同事实及前缀承诺。

22 项测试通过。B=64 最大字段夹具的描述符/封包/交付请求为 5253/5975/6227 字节，终止控制/请求为 5501/5753 字节，均低于 8192 字节限制；这是编码边界测试。另一夹具实际执行 B=4、N=3 的签名加密直方图及计数共享账户作业，把完整 32/8 字节输出输入新编码，账户消费不变，原账本审计通过。该测试没有创建 v2 L3 票据，也没有进行 v2 网络交付。

负面对照确认：受信密钥可以签出格式合法但与真实计算不同的结果，也可以签出两个不同的首次时间。编码和验签不能替代持久准入与首次事件唯一性。新 `retention_delivery_contract.json` 已明确由后续模块实现的事务顺序：发送端同事务绑定稳定请求键、分配序号、创建 L3/描述符/outbox；接收端同锁检查权威、时钟、连续序号和窗口，再提交唯一事实；双方均先权威接受、后本地提交、再回复。完整 uint64 序号采用无损表示，不能直接放入有符号 INTEGER。

格式和确定性回归向量为 `retention_delivery_v2.cddl`、`retention_delivery_vectors.json`；报告为 `retention_delivery_test_results.json`。发送端与接收端持久事务、真实进程中断及本机认证交付已由后续模块验证；独立互通及完整 P2 仍待完成。当前 v1 保持全部记录，无清理或迁移。

## v2 发送端：持久准入、原始证据与清理授权门控

`retention_sender.py` 新增 `RetentionSender` 与 `TLSRetentionSender`，独立配置为 `witnessed-mixed-retention-sender-v2` / `mtls-mixed-retention-sender-v2`。它们在已有签名、加密、混合共享预算及整状态见证之上，增加可信路由、稳定请求映射、v2 发件记录和清理授权表；不修改旧 v1 交付实现，也不隐式迁移旧库。

准入在一个受见证保护的事务内完成：先解析稳定请求键并检查操作/TTL 绑定，再验证当前根、委托/密钥、接收者、公开发布资格及路由；分配递增序号和派生 ID，同时创建原 L3 票据、不可变描述符、发件记录及路由高水位。相同请求始终使用同一身份和原到期时间；改变操作或 TTL、过期、撤销及尚未发布均不能获得新的交付身份。序号使用固定 8 字节大端 BLOB，无损覆盖 uint64，禁止回绕。

完整封包从既有 COMMITTED 结果生成，与原描述符及结果绑定核对后加密持久化，权威接受和本地提交完成后才返回。原票据内的恢复沿用已有撤销语义；路由撤销阻止新的发送准备，过期后的终止控制仍可处理既有事实。终止准备不打开原操作结果；重试始终使用原封包/控制字节。

发送端只接受与已保存请求证据一致的接收确认，同一事实可重复确认，任何不同事实（包括合法签名但不同首次时间）都被拒绝。确认事实与连续确认前缀一起持久化后，才允许签发不超过该前缀的清理授权。接收端清理回复还须与归档前缀一致；原签名请求及检查点加密保留，随清理水位一起进入见证。恢复在提交前审计这些 v2 证据和前缀，避免仅凭数字水位继续工作。

25 项测试全部通过，包含 23 个真实进程退出场景：L3 部分写入、准入提交、结果封包、终止控制、事实确认、清理授权、清理检查点及恢复删除/提交边界。相同请求并发只得到一个 ID，不同请求得到连续序号，两个旧副本最多一个 CAS 成功。独立的认证见证夹具完成计数作业的准入、封包、确认和清理授权，记录 204 次本机认证请求，观察到 TLSv1.2。进程退出场景使用参考见证；不能将单独 TLS 成功夹具说成 TLS 崩溃覆盖。

该发送端套件的回执/检查点由合成接收者签出；下述独立接收端套件已连接实际接收数据库和本机认证网络，验证唯一首次事件、窗口及清理恢复。发送端归档和请求映射保留全部历史，整图像仍有既有容量上限，不构成全系统有界存储。契约及报告为 `retention_sender_contract.json`、`retention_sender_test_results.json`。

## v2 接收端：唯一首次事件、窗口与原子前缀清理

`retention_recipient.py` 提供 `RetentionRecipient` 与 `TLSRetentionRecipient`，每个数据库绑定一条不可变 v2 路由和独立接收端权威命名空间。只有显式引导或恢复可以建立数据库，缺库与旧副本均不能自动重置。状态包含最高序号 H、已清理前缀 F_R、前缀根、时钟下界、最近清理授权，以及恰为 F_R+1..H 的活动记录；活动行数不超过公开窗口 W。

首次事件在同一写锁下核对当前权威、原期限、下一序号与窗口，从完整签名证据重建 ACCEPTED 或 CLOSED，然后将加密事实、证据与 H 一起提交。接收端先取得权威接受，再本地提交，最后签署绑定本次请求和挑战的回执。重复结果必须字节一致，终止查询必须匹配原事实；竞争不能改变首次时间或结论。业务拒绝仍提交已观察时钟；认证失败发生在状态访问之前，基础设施或容量失败不承诺保存该次时钟。

发送端持久确认后生成清理授权。接收端重算目标前缀根，在一个权威事务中删除前缀、推进 F_R/根并保存最近授权，保留 H 与时钟。旧清理请求只报告当前检查点，不反向推进水位或重建历史。已清理序号不能重新接收；普通 FINAL 查询被拒绝，显式 RETIRED 查询只返回检查点，精确历史仍由发送端归档提供。

28 项测试通过，包含 5 项容量准入检查；15 个实际进程退出场景分别覆盖接收 4、关闭 4、清理 4、恢复 3 个边界。另验证回复丢失、窗口满后清理再准入、收件/关闭竞争及两种先后顺序、旧库复活失败、权威图像损坏、身份和签名错误、容量失败保留旧图像。32 轮真实交付/清理保持活动窗口，发送端仍保留 32 条发件历史。参考见证退出测试不等同于 TLS 全故障矩阵。

认证网络夹具通过已有 `RecipientTLSService` / `DeliverySender.exchange` 帧适配器发送 v2 签名对象，实际连接双方独立命名空间/文件/服务/签名密钥。B=4、N=3 的签名加密共享账户直方图与计数进入实际 L3、接收、确认、过期关闭和清理路径。丢失结果回复后得到原首次时间，丢失清理回复后可恢复原检查点；共 894 次发送端见证、14 次接收端见证和 6 次应用交换尝试，观察到 TLSv1.2。所有服务和合成材料仅在本机回环运行。

删除使前缀离开当前规范状态图像，不代表文件、WAL、旧见证图像或备份被安全擦除。两端库及权威仍依赖线性一致、不可回滚的受信服务；同时回退接收库和权威的负面对照仍可产生更晚首次时间。窗口只限制当前接收行数，下节已补上当前镜像的保守最坏字节准入；只读归档检索已由后节接入；归档可用性与规模、见证历史增长、生产密钥管理、独立互通及完整观察证明继续待办。契约和报告为 `retention_recipient_contract.json`、`retention_recipient_test_results.json`。

## v2 接收端当前镜像的字节容量准入

`capacity_certificate` 按真实受信模式与配置计算 M 和 L。每份规范事实、签名证据和最近清理授权都经过 8192 字节帧限制；字段加密固定增加 36 字节，镜像将密文字节编码成双倍长度的十六进制，再加上类型标签、数组、对象及分隔符。M 包含最大元数据与空活动数组；L 是一个最大活动行及一个逗号。因此零行镜像不超过 M，n>0 行不超过 M+n·L−1，活动行数 n≤W 时必不超过 M+W·L。

创建、重新打开或恢复接收库之前，先检查该上界不超过当前 16 MiB 镜像限制；不满足则在连接数据库、写文件或调用权威之前拒绝，不缩小不可变窗口、不重置代际。默认上下文 W=3 的上界为 117875 字节，M=18740、L=33045。最大字段上下文采用较长 TLS 配置名称时 M=19355；W=507 的上界为 16773170 字节，W=508 为 16806215 字节，后者超过 16777216 字节限制。这是充分的保守上界，不是合法业务窗口的精确最大值。

新增 5 项测试检查：超大窗口在文件/权威写入前拒绝；容量恰等于上界时可建立，而少一字节时拒绝；实际序列化的饱和夹具为 16773169 字节，比上界少一字节；真实加密开销与接收、清理、恢复生命周期；降低限制后重新打开时不修改原文件或权威。饱和夹具使用最大长度的假密文，只检验序列化并在本地回滚，未被作为合法事实提交。实际签名业务的生命周期另以小窗口测试，镜像大小依次为 2262、4714、7165、9616、2864、2864 字节。

容量契约见 `retention_capacity_contract.json`。这个门槛只限制单路由的当前规范镜像，不限制物理数据库、WAL、内存、备份、发送端归档、权威提交历史或全部路由之和。旧配置若未满足新保守门槛，该版本会拒绝打开；没有隐式迁移或恢复策略变更，生产部署与离线恢复工具仍待设计。

## 清理后的历史查询与接收端检查点验证

`retention_archive.py` 增加受权审计用的只读归档查询。可信调用方独立提供固定上下文、原接收端检查点请求及签名回复、目标序号；归档分页本身不签名，也不携带结果明文。每页最多 16 条规范事实，总编码不超过 8192 字节，绑定精确检查点、起始序号、前缀根及连续事实。检查点可以是历史版本，它证明相应历史，不证明接收端当前最新状态。

发送端读取在排他写入锁内检查当前权威图像，要求检查点位于已持久记录的清理/确认前缀中，重算该前缀根，读取完整连续事实；返回前再次检查权威。读取期间权威推进便中止，不返回旧副本结果。读取不调用结果解密、不更新时钟、不写账本或权威，不新增签名、费用或交付。路由撤销后仍可执行有权限的历史审计，但这不授权重新交付数据。

`ArchiveVerifier` 从创世根和序号 1 开始，逐页核对上下文、检查点、游标、前缀根及每条事实。只有遍历到检查点水位且最终根完全一致后，才返回目标的原始规范 ACCEPTED/CLOSED 事实与首次时间。此前已处理的事实仍是暂定值，不能视为验证成功；缺页、截断、篡改或重排不会被解释成不存在或 CLOSED。验证器只保存当前根、游标和目标事实；丢失本地进度或接纳了被篡改的中间页后，应以固定检查点从起点重验。

19 项测试通过，包含 3 个实际读取进程退出切点。实际接收端清理后的接受/关闭事实均可恢复；35 次真实交付与清理被分为 5 页，成功恢复序号 17 的原始事实，各页为 2691–2699 字节。最大字段编码夹具的 16 条事实每条 383 字节，整页 6376 字节。另验证只读无结果访问、部分流不返回事实、签名/挑战/路由绑定、跨检查点替换、旧检查点、撤销、旧副本恢复、读取中权威变化、归档损坏及缺失。3 个退出场景验证读取退出不改变账本和权威，不应与已有写入崩溃覆盖累加。

格式、契约及报告为 `retention_archive_v2.cddl`、`retention_archive_contract.json`、`retention_archive_test_results.json`。这仍是内部受权接口，没有公开审计认证服务。分页和验证器工作集有界，但发送端整图像检查、重复前缀扫描及归档历史并未变为有界或高效；完整遍历可能有二次扫描成本。可扩展索引、分层归档、独立副本、可用性、密钥生命周期和完整观察证明继续待办。CDDL 尚未经过独立模式验证或实现互通。

## P2 最小纵向参考演示

`p2_scenario.py` 把原设计的最小演示放在同一次执行中：根授权与两级签名委托 → 两个分析角色并发登记计数/直方图 → 共享祖先额度阻止第三次查询 → 完整机制执行 → 注入提交后回复丢失 → 关闭并重开后用同一请求重试 → L3 准入 → 接收回执丢失 → 撤销阻止新领取 → 原票据恢复 → 写作 → 费用/输出审计。之后还清理接收端记录并验证历史归档。

分析角色是具有不同签名身份的并发 Python 驱动器；写作角色是纯证据到报告适配器，没有调用真实 LLM，不声称进程、容器或提示注入隔离。写作适配器只接收可信上下文、预期操作列表及完整签名交付请求/接受回执，拒绝缺失、篡改、跨操作、重复、终止控制和额外原始快照字段；不能只拿到 ACCEPTED 字样就生成统计报告。

8 项验收测试通过。一次计数和一次四桶直方图分别只生成一份机制随机带；提交后重试没有重新抽样或扣费。两个操作共 16 条扣费记录，审计覆盖 10 个域/祖先账户；共享域消费为 1400000 epsilon 微单位及 16777216 delta Q64 单位。共享中间祖先最多两份成本，即使域仍有余额，第三次查询也被拒绝。撤销阻止新领取，原有效期内已准入票据按原语义恢复。

该次运行记录发送端见证 908、接收端见证 10 次认证请求及 4 次应用交付/清理尝试，观察到 TLSv1.2。结果使用真实新随机带，演示输出和并发准入顺序不要求每次相同；验收要求同一操作的重试保留同一结果。故障为提交后的 API 回复丢失和接收回复的实际连接丢失，本套件没有新的进程死亡场景，也没有效用或性能基准结论。

复现：`python3 test_p2_scenario.py`。逐步证据见 `p2_scenario_results.json`，测试报告保存其摘要及源码摘要；验收映射见 `p2_scenario_contract.json`，全阶段状态见 `../phase_acceptance_matrix.json`。P2 最小参考演示通过，但真实身份/LLM 输入边界、真实分类与全局血缘、L3 前事件和跨路由公开观察、生产故障域、完整证明与独立互通仍未闭合。P4 正确组合强基线、同预算效用及性能，P5 隐藏授权，P6 TEE/MPC 均保持原范围，不因当前参考演示通过而移除。
