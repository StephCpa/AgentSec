# 恢复过程中反复中断的组合验证

本轮把“恢复本身再次中断”接到三类已有轨迹：公开请求、私有计算槽、接收与发送确认。目标不是只证明一次恢复能够完成，而是检查部分恢复不能形成可用的残缺状态，已经完成但未返回的恢复也不能重复执行业务。

基线为 `463b84a8551b98415efa96c4ed7d57b348fa795f`。新增组合模拟器、实际恢复退出驱动、归档重放与专项回归；未修改生产协议或恢复实现。配置细节见[范围契约](recovery-interruption-contract.json)。

## 组合规则

[组合模拟器](../../outputs/agent-cryptography-design-20261025/prototype/recovery_interruption_simulator.py)包装既有公开请求、私有槽或交付故障模拟器。原始故障先确定权威逻辑状态及待恢复目标；之后 `RECOVERY_CUT` 只更新公开时钟，不改变业务状态、预算、已批准输出、首次事实、最终前缀或待重试槽。

公开观察为 `RECOVERY_UNAVAILABLE(at, side, operation)`。它不包含切点、本地提交位、见证版本、摘要或数据库内容。切点是数据无关的显式环境计划；模拟器既不读取实际恢复结果，也不从真实错误推断切点。成功的 `RECOVER` / `DELIVERY_RECOVER` 仍由环境单独声明。

即使在 `after_recovery_commit` 退出，本地副本已完整恢复，模型仍等待显式恢复完成事件。这不表示生产 Guard 会拒绝已经有效的副本。本配置由可信驱动暂停业务，直到最后一次恢复正常返回；测试分别验证当前副本可以通过状态检查、落后或无 anchor 副本必须被拒绝。

## 两种起点与六次连续退出

每个原始故障状态分别运行两种恢复起点：

- **现有副本**：保留业务故障退出后的本地镜像；它可能仍与权威一致，也可能落后。
- **全新副本**：通过实际 `new_replica` 初始化空数据库，尚无 witness anchor；不能把空副本误判为已恢复。

随后依次中断：删除旧行后 → 本地恢复提交前 → 本地恢复提交后，并将这三个切点再重复一次。前三次覆盖首次恢复尚未提交与已提交；后三次检验对一个已恢复镜像再次删除、重建和退出的行为。最后仍执行原配置的正常新副本恢复，继续原请求、原槽或原回执重试。

[实际驱动](../../outputs/agent-cryptography-design-20261025/prototype/recovery_interruption_trace.py)使用独立子进程执行真实 `recover_from_witness`，在现有钩子调用 `os._exit(96)`。切点不可达、退出码不同或超时均失败。恢复子进程还对采样、私有步进、公开业务分派、发布、传输准备、确认及见证写入入口设置失败守卫；恢复允许审计和解密存储，但不能重新分派这些业务动作。

## R12 与权威状态关系

每次恢复退出都核对：

1. 所有发送端、接收端见证头与镜像逐字节不变，不能将本地恢复变成新的权威提交。
2. 提交前退出保留恢复前的完整本地镜像和可选 anchor；提交后退出同时得到完整权威镜像和对应 anchor。
3. 全新副本前两次退出后仍没有 anchor，业务状态检查必须拒绝；第三次提交后 anchor 存在，后续退出不能留下半删除状态。
4. 已有当前副本在提交前退出后仍是当前副本；已有落后副本在恢复提交前仍被 Guard 冻结。两者不混为一种“失败后都拒绝”的规则。
5. 用独立临时诊断副本读取权威状态，在每个切点核对 R1–R8；私有槽场景额外核对 R10 中的随机带和内核前缀。诊断数据不进入模拟器。

R12 保存这些成功谓词的摘要，避免把私有镜像摘要加入跨数据集的公开对应比较。诊断恢复只供检查，与最后继续执行的正常恢复分别计数；原交付配置已有的诊断恢复也单独列明。

设某次恢复读取的权威状态为 W，本地原状态为 L。当前固定权威头配置下，提交前退出应保留 L，提交后退出应得到 W；两种情况下 W 不变。由此可以连续应用相同检查，而不把恢复当成业务转移 T(W)。这是有限执行所验证的条件关系，未证明权威并发变化、任意故障计划或断电语义。

## 十个组合场景

| 来源 | 原始故障状态 | 需要保持的关键事实 |
|---|---|---|
| 公开请求 | SUBMIT 见证提交前 / 后 | 请求日志、预算预留、原请求缓存重试 |
| 私有槽 | 计数 L1 已采样但未提交 | 原物理样本可被丢弃；恢复不能新增采样或收费 |
| 私有槽 | 直方图 L1 已提交 | 原随机带与一次已提交 L1 保留 |
| 私有槽 | 计数最终槽未提交 / 直方图最终槽已提交 | 结算、结果、发布及原槽精确重试 |
| 接收 | 首次接收提交前 / 后，恢复时票据已到期 | 无事实则 CLOSED/170；已有事实仍 ACCEPTED/100 |
| 确认 | 最终事件写入前，后继项已 WITHHELD | 确认与可推进前缀不出现部分状态 |
| 确认 | 见证已提交且存在后一路由 | 原确认与跨路由最终顺序保留 |

各场景使用三个合成用户的八个子集，条件输出固定为计数 1 或四桶直方图 `(1,0,0,0)`。数据集比较支持条件轨迹一致性，不是输出分布或端到端隐私证明。现有副本与全新副本的内部 R12 状态不同，因此跨副本模式只要求公开观察相同；同一模式下再比较数据集邻接关系。

负对照包括：把中断直接当作恢复成功、恢复时额外推进一个私有逻辑槽。两者必须被拒绝或导致重放差异。拒绝额外私有字段、错误恢复目标、无待恢复状态以及倒退时钟的检查同时保留。

## 复现与证据边界

独立矩阵完成 **10 个原始故障状态 × 2 种副本模式 × 8 个数据集 = 160 个组合场景**，包含 160 次原业务退出和 **960 次恢复过程退出**。最终正常恢复 160 次；恢复切点诊断恢复 960 次，原交付配置额外诊断恢复 64 次，分别计量。共核对 **26,864 个状态检查点**。

160 个归档重放、480 个有向用户增删邻接对检查、80 个跨副本模式公开观察比较全部通过。十二项专项回归通过，包括两个错误模型负对照。完整验证通过 **30 个原有测试套件、172 项仓库回归及 7 个模型入口**；本轮十二项包含在 172 项内。上述场景、检查点和回归存在重叠，不能相加为独立安全性质。
