# 九类实验共用的观察事件契约

本轮将现有正常执行、公开请求故障、私有工作故障、交付故障、恢复中断、准备中断、清理、窗口补充和跨路由配置接到同一个事件表示。原有状态机、协议与持久化路径没有改变。它解决记录解释与校验的一致性问题，是统一公开轨迹语义的一步；并未把九类允许的调度合成为一个新状态机。

## 输入、返回和环境必须分开

旧记录中的字段不能只按名称解释。例如 `CONFIRM` 和 `RETIRE_CONFIRMATION` 的 `response` 是此前已经收到、现在提交给发送端核验的回执。它不是确认调用新生成的回复。故障记录里仍出现这个字段，也不表示本次确认成功返回。

共用表示 `agentsec-observation-event-v1` 包含以下部分：

| 部分 | 保留内容 | 解释边界 |
|---|---|---|
| `at` | 声明的公开时钟 | 实验输入，不是测量所得的耗时 |
| `call` | 逻辑入口、调用角色、参数、输入报文及已有回执 | 角色是实验角色；不授予真实权限，也不证明进程隔离 |
| `outcome` | 完整返回字节、完成、业务异常、明确的可用性异常或没有返回 | 完成不等于新提交；没有返回不等于回滚 |
| `environment` | 故障切点、丢包原因和预先供应的公开随机数 | 保留供复现；从局部调用者视图中排除 |
| `source` | 旧命令和事件类型 | 保留可逆来源；从局部调用者视图中排除 |

`caller_view` 是相应调用角色的局部 API 视图，包含上述公开时钟、调用和结果。调度步属于可信调度器，恢复属于恢复操作者，公开网关、交付与清理调用也分别标注角色。把所有角色的视图合并仍不是一个已定义并证明安全的部署攻击者视图。

包在到达接收方前丢失与接收方处理后 ACK 丢失，在此调用者 API 抽象中都表现为没有返回。原实验的两种标签仍完整保存在可逆表示的环境部分，不能由这个局部视图推断接收方是否已提交。完整网络观察、超时和传输异常的进一步细分没有在本轮建立。

旧的 `*_CUT` 失败记录没有具体异常时仍表示 `no_return`，不补写 `WITNESS_RECOVERY_REQUIRED`。跨路由配置实际捕获的该异常保留为 `exception` 和原异常码。业务拒绝单独保存原代码；签名公开网关回复（包括签名 `REJECTED`）则保留完整字节，不改成一个通用异常名称。

## 可执行边界

[事件模块](../../outputs/agent-cryptography-design-20261025/prototype/observation_events.py)冻结当前 24 种命令和 30 种命令／事件配对，校验字段集合、字节表示、类型、调用参数绑定与时钟。可逆转换拒绝缺字段、额外进度字段、篡改入口或调用角色。流检查还要求确认所引用的请求／回执对之前确实作为返回被观察到，ACK 丢失不产生可供确认的回执；检查失败不推进流状态。

这不是完整协议解析器：字节表示校验不认证签名，也不验证报文内的操作身份、策略、预算或数据血缘。故障切点的可达性、允许的交错、拒绝码的公开原因和机制调用仍由原配置及其状态关系负责。未知事件形状被拒绝；不能用一个格式正确的代码证明其来源与私有数据无关。

## 验证结果

[归档审核器](../../outputs/agent-cryptography-design-20261025/prototype/observation_events_audit.py)扫描九类完整历史归档，共 **3,432 个案例、649,920 条事件**。每条记录均通过共用契约、可逆还原和流检查，全部 24 种命令及 30 种配对都出现。扫描没有重新执行这 3,432 个案例，也没有重新证明历史运行的数据库状态关系。

| 统一结果 | 历史事件数 |
|---|---:|
| 完整返回字节 | 28,776 |
| 调用完成 | 610,848 |
| 没有返回 | 6,016 |
| 业务异常 | 4,152 |
| 明确的可用性异常 | 128 |

50 条测试输入由归档的确定位置抽取，审核器重新抽取并核对内容及来源摘要。它们覆盖上述配对、五个公开网关方法和六种公开回复状态。针对字段遗漏、异常伪造、旧回执误作输出、丢包原因误作结果、未观察到的回执、非法字节、时钟回退和角色篡改的负对照均通过。

[新增测试](../../tests/test_observation_events.py)的 **14 项测试通过**；其中一项分别重新运行九类实际入口，再将真实运行与原独立模拟器已比较一致的轨迹送入共用契约。这是九个新运行的集成检查，不是九类全部调度空间的重跑。另外六项验证运行器测试通过；新的测试模块与输入会随现有自动发现机制进入 CI。

## 复现

```sh
python3 -m unittest discover -s tests -p test_observation_events.py -v
python3 outputs/agent-cryptography-design-20261025/prototype/observation_events_audit.py \
  --fixtures tests/fixtures/observation-events.json --output /tmp/observation-audit-new.json
python3 outputs/agent-cryptography-design-20261025/prototype/observation_events_audit.py \
  --extract-fixtures --output /tmp/observation-fixtures-new.json
```

输出路径必须是新文件。归档审核绑定每个历史摘要与压缩输入、每个完整原案例、统一表示和局部调用者视图。摘要用于追溯与防止意外丢信息，不独立证明原实验或规范正确。
