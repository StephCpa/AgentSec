# 在公开事件边界检查真实状态与生成器状态

PR #3 已提供从公开输入构造签名报文的候选生成器。本轮继续推进它依赖的 R1–R4 状态关系：在初始状态，以及每个已完成的 PUBLIC、TICK、SEND、CONFIRM 事件之后，读取真实账本的指定字段，与独立推进的公开模型逐项比较。

这里“独立推进”指状态实例和执行路径分离。生成器仍共享原校验器的预测转换规则及公共编解码器，不能据此称为完全独立实现。新增检查器是测试侧诊断工具，可以读取真实数据库；这些读数不会作为生成器输入。

## 新增检查的必要性

之前的运行驱动在轨迹末尾比较账户的 `reserved + spent` 与模型已分配金额。这不足以区分“正确预留”与“提前记为支出”，也无法定位已被后续步骤掩盖的临时偏差。新关系分别比较每个账户的总额、可用额、预留额、已支出额，并核对每项操作、每个祖先账户的费用状态。

| 关系 | 本轮检查的真实字段与对应条件 |
|---|---|
| R1 请求与身份 | 公开请求序号连续；请求身份和原始响应缓存一致；挑战的主体、期限、使用状态一致；已消费证明绑定原 nonce、操作和原始证明；完整凭证命名空间、摘要、链位置、签名 Action、静态密钥与主体登记一致 |
| R2 费用与 L1 | RESERVED/STARTED 的费用为 HELD，COMMITTED/BURNED 为 SPENT，CANCELED 为 RETURNED；逐账户四项金额一致；操作阶段、代次及 seed/result 存在标记一致；真实随机带创建次数、操作类型、L1 槽与模型调用记录一致 |
| R3 公开工作 | tick 与重试记录连续；next_seq、publish_seq、round-robin cursor 一致；每项任务的 seq、pc、work、suppressed 一致；暂停状态一致 |
| R4 发布与期限 | 根撤销状态、权威绑定和交付绑定一致；从已存储的公开凭证和全部祖先密钥重新计算授权上限；发布槽、准入决定、原始票据时间、路由序号和 descriptor 一致 |

R2 中，STARTED 仍保留 HELD，直到成功完成或取消后转为 SPENT。它已经不可退款，不能把 HELD 误读成“仍可释放预算”。执行前过期会取消并退回费用，执行开始后才过期则完成固定工作并记费，最终 WITHHELD。

检查器只查询 seed/result 是否存在，不解密随机带或结果；它不读取私有快照和工作累加器。SQLite 授权回调测试会拒绝检查器写入数据库或读取私有工作列。它检查的是已完成事件边界，不是事务内部每条 SQL 或见证提交的中间故障点。

## 驱动与输入隔离

`StepwiseRuntime` 复用此前真实执行计划，在真实事件加入观察记录时触发检查。对应的公开命令已在调用前记录。生成器先消费该命令；仅当生成完毕后，驱动才把生成的观察与真实观察比较，再调用数据库关系检查器。

已批准输出来自公开实验目标和操作形状，仍为按操作绑定的理想机制资源。实验目标不是通过查询真实结果得到的。生成阶段禁止打开 SQLite、调用真实网关和进入读取既有响应的校验路径。签名仍由显式合成签名接口提供。

每个检查点归档 R1–R4 投影摘要。摘要匹配用于核对运行记录；单独持有这些摘要无法证明代码正确。重新执行实验才能重新检查数据库关系，不能把对摘要文件的重放称为对真实状态的再次验证。

## 对归纳证明的贡献与缺口

这些检查把 R1–R4 从文字要求转成可执行断言。它们能指出首次出现差异的事件，并能阻止“报文暂时相同所以状态必定对应”的错误推论。它们仍不是对任意允许输入的归纳证明。

需要继续完成的转换义务包括：

1. **初始关系**：对所有符合部署契约的配置证明关系成立。当前只覆盖固定合成配置，并在测试中对四类祖先密钥分别设置较短的初始期限。
2. **公开请求转换**：逐分支证明认证失败、精确重试、身份冲突、过期、策略拒绝、成功提交与控制转换都保持 R；当前由有限计划和回归用例覆盖。
3. **L1 与工作转换**：证明原随机带在首次私有读取之前持久化，后续执行使用同一带；当前只核对成功调用与已完成边界的存在标记，不把标记当成持久性证明。
4. **发布转换**：证明完成、取消、撤销和期限边界在任意合法交错中保持同一决定；任意长队列、动态管理和故障交错仍未穷尽。
5. **R5–R8**：发送准备、接收首次事实、持久确认、最终前缀和分页的报文比较继续保留，但本轮尚未把其全部真实存储状态纳入逐步关系。

关系检查未覆盖见证历史、物理时间、磁盘流量、资源耗尽、生产密钥建立、崩溃恢复、清理和任意晚到报文。此前持久化成本实验保持不变；在优化持久化方案时，需要用这些断言回归逻辑语义，并另行保留崩溃/恢复和实际成本验证，不能用关系检查代替它们。

## 本轮结果

- 25 组、200 个案例全部通过，共检查 35,136 个初始/已完成事件边界。每组 8 种输入的公开轨迹与关系投影摘要一致；600 个有向相邻比较仍是固定输出条件化证据。
- 200 个生成轨迹摘要均与 PR #3 已归档的构造实验一致；检查点编号、事件种类和数量均与原公开输入序列对应。该交叉核对不重新执行真实数据库关系，区别于上面的完整实验。
- 最终隔离副本中 49 项仓库回归测试及 17 项既有公开轨迹测试通过。其中新增状态关系测试 13 项，含人工破坏缓存、证明关联、费用状态、L1 槽、调度位置、发布决定、期限和 descriptor 的负例。
- 四类密钥（authority、manager、worker、leaf）的短期限配置均被纳入授权上限测试；执行前/后过期分别得到退款/记费并 WITHHELD 的预期状态。

原始结果、日志和源码摘要见[证据清单](stepwise-evidence-20261026/manifest.json)、[实验摘要](stepwise-evidence-20261026/summary.json)、[运行记录](stepwise-evidence-20261026/run.json)和[归档交叉核对](stepwise-evidence-20261026/archive-check.json)。源码基线是 PR #3 的 `5b775ccb360ca03272618dfc9c79d6262c08172d`；新增源码由本轮运行摘要分别绑定。该基线的 push 与 pull_request CI 均成功，具体运行链接在清单中。

## 复现

在仓库根目录运行，使用尚不存在的输出目录：

```sh
python3 outputs/agent-cryptography-design-20261025/prototype/stepwise_trace.py --output /tmp/agentsec-stepwise-new
python3 -m unittest discover -s tests -p test_state_relation.py -v
```

该计划覆盖此前的 19 类轨迹，以及普通/自适应轨迹在额外输出 0、2、3 下的分支。每组使用 8 种合成私有输入；随机带为指定输出构造，所以相等性只属于条件化证据，不是输出分布检验。
