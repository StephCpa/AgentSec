# 公开请求进程中断与恢复对应

本轮把真实子进程退出接到构造性公开模拟器与状态关系上，补充“请求没有返回响应，但见证可能已经提交”的受限边界。原公共网关协议与实现没有改动；新增的是独立故障配置、生成器扩展、实际进程驱动和可重放证据。

## 从正常轨迹扩展到不可用状态

此前 R1–R8 检查已完成事件后的本地状态。本轮额外定义 `PUBLIC_CUT` 输入：客户端的签名请求、身份指纹、公开时钟和挑战随机币，与预先指定的退出位置。退出位置是与私有数据无关的环境输入，不由实际响应、异常、见证摘要或数据库状态推断。

模拟器根据同一公开请求构造候选业务结果和签名响应：在见证提交前退出，回退其逻辑变更；见证已提交时，保留权威逻辑状态与缓存。两种情况都只生成 `PUBLIC_UNAVAILABLE`，其中没有响应、异常内容或切点名称。随后要求显式 `RECOVER` 协调事件，才能继续公开调用、调度或交付。

`PUBLIC_UNAVAILABLE` 表示测试调用方在子进程退出后没有收到返回值，**不是新网关状态码，也不是已经实现或验证的 TLS 错误报文**。`RECOVER` 是可信协调器事件。签名资源与既有候选模拟器相同；模拟器可能构造真实进程退出前尚未来得及签名的潜在响应，其签名调用数只作诊断，不属于声称匹配的公开服务观察。

## 六个退出位置

子进程打开实际账本和独立 SQLite 见证文件，在指定钩子使用 `os._exit(93)` 退出；不执行 Python 异常清理。父进程检查退出码后重新打开本地副本，再从权威镜像恢复一个新文件。

| 退出位置 | 见证已提交 | 本地已提交 | 恢复前状态 |
|---|---|---|---|
| 业务效果写入后 | 否 | 否 | 原状态 |
| 请求日志写入后 | 否 | 否 | 原状态 |
| 见证接受前 | 否 | 否 | 原状态 |
| 见证接受后 | 是 | 否 | 本地落后，原保护逻辑拒绝推进 |
| 本地锚点写入后、事务提交前 | 是 | 否 | 本地落后，原保护逻辑拒绝推进 |
| 本地提交后丢弃返回值 | 是 | 是 | 已提交状态，调用方未收到响应 |

这验证本机进程退出与 SQLite 事务边界，不模拟断电或见证自身回滚。

模型还验证切点可达性：缓存请求与认证/过期阶段直接拒绝的请求不会经过新业务/新日志钩子，对这些请求指定相应切点时，以 `CUT_NOT_REACHED` 拒绝且不改变模型状态。该规则通过六个负对照覆盖；不是将不存在的实际失败归一化为无响应。

## R9：恢复前后的关系

在不可用事件处，不能错误地要求陈旧本地副本已经等于权威模型。该处检查 R9：见证序号是否按切点恰好推进一次、镜像摘要是否有效、本地事务是否保持旧状态或完整提交、现有保护检查是否拒绝落后副本。实际见证摘要只在诊断层使用，不传给生成器或公开事件。

恢复到新副本后，检查原始镜像逐字节相等、本地审计通过、恢复没有改变见证头；再要求 R1–R8 与生成的权威逻辑状态相等。所有其他已完成事件仍检查 R1–R8，`RECOVER` 同时检查 R9。恢复模型本身是权威逻辑状态上的停留步骤，不通过读取恢复数据来补全预测。

负对照故意将“见证已提交”误建模为未提交，或反向误分类。这两种模型都能生成同样的无响应事件，但恢复后的日志关系会拒绝它们，说明仅比较表面失败响应不足以覆盖提交边界。

## 工作负载与过期重试

九种计划包括挑战、计数提交、直方图提交、L1 前/后取消、策略拒绝轮询、过期首次提交、过期精确重试、最终页查询。普通计划覆盖六个切点；缓存精确重试不经过新业务/新日志钩子，因此只覆盖四个实际可达切点，共 52 组。每组遍历 N=3 的 8 个二值数据集；固定已批准输出为 1 或 `[1,0,0,0]`，比较同一公开输入和故障计划下的条件轨迹及关系摘要。

首次跨数据集测试发现通用夹具会生成随机证明 ID，导致两次运行的公开输入不同。驱动器已按公开请求序号固定证明 ID；这修正的是实验控制条件，不是协议漏洞。没有删除不同的观察或从真实响应提取随机币。挑战币同样由公开请求序号确定，是与私有数据无关的可复现实验输入；本轮没有检验真实随机源的分布。

过期计划在请求创建窗口于 160 结束后，于 161 恢复并重试；动作本身的有效期仍允许后续执行：

- 若首次请求在见证提交前退出，重试为 `REJECTED`，没有登记操作或调用机制。
- 若首次请求已提交，重试返回原始 `RECORDED`，不再次消费证明或重复预留预算。
- 已成功返回过的精确请求，即使再次在任一可达切点退出，过期重试仍返回原响应；其机制调用保持一次。
- L1 前取消返回预留，L1 后取消保留支出；两者最终均为 `WITHHELD`，内部预算阶段仍分别检查。

## 本轮结果与证据

修正切点可达性规则后的矩阵共 **416 次实际子进程退出、416 次新副本恢复、48,680 个检查点**，全部通过。检查点包含初始状态：其中 48,264 处检查 R1–R8，416 个不可用事件仅检查 R9，416 个恢复事件在 R1–R8 外增加 R9。

52 组各自的 8 个数据集具有相同条件公开轨迹和检查点摘要；另显式枚举并核对了 1,248 个有向相邻数据集对。该比较固定了已批准结果和故障计划，不是输出分布或完整差分隐私实验。

独立重放全部 416 条归档命令序列，逐字节消息和显式签名资源调用记录均匹配。源码摘要门槛会拒绝旧版本证据。8 个负对照包含两种提交边界误分类、以及六种不可达切点，均按预期拒绝。

本地统一验证通过公开网关 23 项、见证账本 19 项、公开转录 17 项、仓库回归 117 项和 7 个模型入口。新增 10 项专项测试包含在 117 项内；这些与原有套件重叠，不相加解释为独立安全覆盖。
