# 从校验既有报文到生成公开报文

本轮在 PR #2 的受限轨迹和成本实验之上推进一个新的义务：给定公开输入、已批准机制输出和明确的签名接口，能否**生成**与真实实现相同的可观察报文。新工作位于独立分支，原 PR #2 的数据和摘要保持原样。

## 新增的构造

`PublicSimulator` 不接收真实响应。它接收五类资源：公开配置、调用方签名请求与证书身份、公开逻辑调度/传输决定、绑定操作的机制输出，以及按 gateway/sender/receiver 分角色的签名回调。签名回调返回的内容会按公开密钥、签名域和原请求 payload 重新核验。

这正面处理了上一轮的缺口：公开验签密钥本身不能生成有效签名。我们将签名接口作为理想世界的显式资源，实验中用固定的合成服务密钥实现它。密钥建立和该接口独立于私有数据仍是前提，不是已证明的生产事实。

模拟器生成网关的签名响应、完整交付封包、过期终止控制、带挑战的发送尝试和可见接收回执。它复用原响应缓存，所以精确重试不重新签名。首次 ACCEPTED/CLOSED 事实由公开传输事件和逻辑时钟构造；只有显式 CONFIRM 输入才能推进发送端最终前缀。

在实验驱动中，每条命令均在对应真实调用之前记录。挑战随机量按公开请求编号固定，发送挑战按公开事件编号固定，不通过解析真实响应来反推输入。生成阶段关闭真实运行实例，并禁止打开 SQLite、调用真实网关或调用校验器的“读取观察响应”入口。驱动本身仍能读取合成数据来选取有效随机带，且与模拟器分离。

签名服务失败时中止生成，不制造正常 REJECTED。局部模型状态回滚便于定位问题，但这不是“异常不泄露信息”的声明。PACKET_LOST 不创建接收状态；ACK_LOST 记录首次接收事实但不提供丢失 ACK 的字节。这里的“完整”仅指既定观察字母表，不包括所有物理网络观察点。

## 对应关系与尚需证明的归纳步骤

令 R 把真实受限账本与公开模型状态关联起来。下表是需要逐步保持的具体关系；目前的程序与有限试验提供实例证据，尚未完成对所有允许输入的归纳证明。

| 关系 | 真实状态 | 模拟器状态与公开效果 |
|---|---|---|
| R1 身份与重试 | `gw_requests`、固定主体登记、原始 Action | 请求身份缓存、原响应字节、scoped credential identity |
| R2 预算与 L1 | 域/祖先费用，原随机带创建 | allocated=reserved+spent；一次 L1 oracle 调用绑定原 Action 摘要与槽 |
| R3 固定工作 | jobs 的 seq、pc/work 和调度 cursor | 公开槽驱动 round-robin；取消后的 dummy 槽仍执行 |
| R4 发布与准入 | 原子 ADMITTED/WITHHELD、原票据 | 同一决定与期限，包含全部祖先授权上限 |
| R5 交付身份 | 首次准备的封包/控制和路由序号 | 同一 descriptor、已批准结果、原封包摘要、缓存签名字节 |
| R6 首次接收 | 不可替换的 ACCEPTED/CLOSED 及事件时间 | 从首次可达 SEND 与公开时钟构造事实；ACK 丢失不改事实 |
| R7 发送确认 | 发送端持久确认和连续最终前缀 | 显式 CONFIRM 后推进；仅收到 ACK 不足以推进 |
| R8 观察与分页 | 签名公开响应和 cursor | 在 R1–R7 成立时，生成相同状态词、页内容和字节 |

条件论证的结构是：假定 R 初始成立，逐条证明每个允许的公开输入使真实转换与模拟转换保持 R，并产生相同观察；再将调用方下一步选择作为此前公共视图的函数，递归耦合整个交互。对坏签名和策略拒绝，还必须证明两边对同一输入作出相同判断，并且失败不能依赖未计费的私有状态。

在这个对应关系、理想资源独立性、完整保护域和公开机制调用上界 m 都成立之后，才可组合单次机制的 `(0.7, 2^-41)` 成本，得到 `(0.7m, m·2^-41)` 的目标界。两次机制目标为 `(1.4, 2^-40)`；这仍是带前提的目标，不是本轮实验已经证明的系统 DP。

## 本轮可重放结果

归档见 [证据清单](constructive-evidence-20261026/manifest.json)、[实验摘要](constructive-evidence-20261026/summary.json)与[离线重放结果](constructive-evidence-20261026/replay.json)。基线为 PR #2 的 `ab303a30192a98464ee9844d1e3d16b55e3768b4`，实验摘要额外绑定本轮全部原型源码摘要；不能用基线提交代替这些新增源码摘要。

- 19 类公开计划均在 8 种合成私有输入上执行；另对普通和自适应计划补充首项输出 0、2、3，共 25 组、200 个案例。原输出 1 的自适应路径选择直方图，输出 0、2、3 的路径选择计数。
- 全部 34,936 条观察记录与真实执行逐字节相同；每组 8 种输入的条件化轨迹一致，对应 600 个有向相邻输入比较。这里的随机带为指定输出构造，因此不代表 600 次独立随机试验，也不是对完整输出分布的检验。
- 归档的 200 个输入序列离线重放通过。重放脚本先核对实验源码摘要，再仅向生成器传入配置、已批准输出、命令及合成签名接口，生成完成后才比较期望响应、签名调用和轨迹摘要。SQLite、真实网关及读取观察响应的入口在生成阶段被禁止。
- 最终隔离副本验证通过 36 项仓库回归测试（其中新增模拟器测试 11 项），以及既有公开轨迹入口的 17 项测试。完整运行版本和源码摘要见 [run.json](constructive-evidence-20261026/run.json)。这次本地检查只重跑上述入口，未将旧报告冒充为本轮完整套件结果。

复现时，从仓库根目录运行 README 中的构造实验和离线重放命令；输出目录/文件必须使用新路径，避免覆盖已有证据。归档只含合成身份、签名测试材料和合成数据产生的报文。

## 为什么仍不能宣称完整精化

生成器共享校验器的预测转换规则与公共解析器。真实实现与生成输出逐字节相同，比“校验器接受现有报文”增加了构造性证据，但不是独立实现互检，更不是自动完成 R 的证明。

此外，当前 SEND 表示对当前未确认前缀的新的准备/发送，不覆盖已确认报文的任意晚到副本；实验只有一个共享逻辑时钟；公开命令由有限计划产生。资源耗尽、磁盘/见证故障、动态管理、崩溃恢复、清理、时钟偏差及任意自适应调用序列仍需扩展对应关系。尤其不能因为模型忽略后端见证流量和物理时间，就认为这些观察已被隐藏。

下一步应优先对 R1–R4 写出逐分支的归纳或机器可检验义务，再把真实恢复与清理加入驱动事件。持久化分段优化应等这些语义明确后比较，并保留 L1 前持久化原随机带、固定公开工作形状与未知接收事实的阻塞规则。
