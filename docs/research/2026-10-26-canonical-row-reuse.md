# 在单次镜像构造内复用规范行编码

本轮移除了完整状态镜像构造中的一次重复编码。六组本机查询中，同一最终快照的镜像构造 CPU 中位耗时降低 15%–25%，执行阶段中位耗时降低 8%–24%。镜像格式与字节、见证提交次数、公开逻辑调度和恢复检查保持原定义。数据支持减少编码工作，不支持关于生产吞吐、物理隐私或全系统安全完成的结论。

## 原因与实现

原 `WitnessedLedger.state_image()` 先将每行转换为带类型的单元格列表，再调用 `canonical(row)` 得到排序键。排序后构造完整对象，并调用一次 `canonical(image_object)`；此时已用作排序键的所有行又被编码一遍。

新实现保留每行的规范字节，将它同时用于排序和最终 JSON 数组拼接。只在当前函数调用内保存这些字节；每次调用仍读取完整模式和全部表。事务开始时的完整镜像检查、提交时的完整镜像和 CAS、恢复中的重建/审计/见证重检查均保留。

基线固定为提交 `06005e36cec9040fb35eaa9d03858c75ac0be0e7`。实验文件的 `reference_state_image` 保留旧函数体，已核对其 AST 与该提交相同，摘要见[契约](canonical-row-reuse-contract.json)。它只用于测试和成本比较，主路径直接使用新实现，没有运行时切换开关。

## 字节相等的结构论证

设 `C` 为原规范 JSON 编码，`R` 为一张表的已打包行列表。旧实现的表内容为：

```text
C(sorted(R, key=C))
```

规范数组编码满足：

```text
C([r1, ..., rn]) = '[' + comma_join(C(r1), ..., C(rn)) + ']'
```

因而旧输出等于新实现的：

```text
'[' + comma_join(sorted(C(r) for r in R)) + ']'
```

排序键相等时，对应编码字节也相等，不需要假定原始行互不重复。空表输出仍是 `[]`。表名先按 Python 字符串排序，再由原编码器编码；不能按转义后的字节对表名排序。最外层字段依次为 `columns`、`format`、`rows`、`schema`，与原 `sort_keys=True` 顺序相同；列、模式、表名、行中的字符串均继续使用原编码器，因此转义字符不能注入 JSON 结构。

在相同稳定数据库快照、原 `pack_cell`/`canonical` 定义不变、存储值属于原支持集合的前提下，两种构造得到完全相同的镜像字节。长度检查与域分离摘要因此不变。这是序列化算法的结构论证；不是对任意并发数据库读取或整个密码系统的机器证明，也不构成独立互操作实现。

## 实验方法

计数/直方图分别使用轮询间隔 0/1/8，共六组。每组运行 3 个新旧实现对照对，顺序为旧/新、新/旧、旧/新；每次使用新建状态和相同公开配置、合成数据及已批准输出。计数保持 85 个逻辑槽，直方图保持 337 个逻辑槽。

完整执行阶段只计 `finish()`，排除初始化、提交注册、交付、审计和模型生成；耗时使用 `perf_counter_ns`。逐次镜像构造的 CPU 使用 `process_time_ns`。两种实现均采用相同测量包装，报告保留所有样本。各对照对逐项核对逻辑槽、轮询数、两次镜像构造/事务、CAS 数、镜像总字节、生成公开轨迹摘要和 R1–R8 最终状态关系。

各组最后一次新实现运行还在**同一份最终快照**上交替执行 16 对编码，严格比较镜像字节并测量 CPU；同时从原始见证恢复新副本，检查原始镜像、审计与 R1–R8 最终关系。恢复检查中的每次镜像构造也调用冻结旧算法对照。

例如直方图每槽轮询仍有 674 次执行期 CAS，累计原始镜像为 211,148,997 字节，两次镜像构造/事务保持不变。其执行阶段中位耗时由 7.207 s 降为 5.505 s；并未通过减少提交、略过完整状态核对或改变对外轮询语义获得改进。

18 个查询对照对中，17 对耗时下降；计数每 8 槽轮询的一对耗时上升 2.68%。表格报告各组中位数，不表示每次运行必然更快；这种波动也是不设生产收益保证或 CI 时间阈值的原因。

[原始数据](row-reuse-evidence-20261026/cost.json)包含每次顺序、样本、源码摘要及环境版本。这里没有网络见证，不能将数值解释为 mTLS 或远程性能；3 次查询样本也不足以稳定估计尾延迟。没有设置 CI 性能阈值或宣称在其他设备上的固定加速比例。跨实现的查询使用新加密状态，密文字节可以不同；逐次镜像编码对照使用的是同一数据库快照，要求严格逐字节相等。

## 验证边界与复现

新增专项覆盖空模式/空表、Unicode 与转义名、字符串与 BLOB、整数边界、空值和重复行、插入顺序、模式修改、事务回滚、外部连接修改、旧镜像上限与不支持类型拒绝。篡改发生在已构造过镜像之后，仍由 `LOCAL_STATE_DIVERGED` 拒绝；不存在跨调用缓存。

六条代表性轨迹在**所有镜像构造处**叠加新旧字节对照，包括普通交付、回执未确认后终止、未确认之前的 WITHHELD、跨路由过期、精确重试/拒绝、自适应第二项查询；原逐事件 R1–R8 检查同时运行。这些场景与原套件有重叠，不相加解释为独立安全覆盖。
