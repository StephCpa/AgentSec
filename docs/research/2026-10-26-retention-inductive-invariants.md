# 接收窗口与副本身份的参数化归纳义务

有限故障矩阵说明具体执行与预期对应，但不能仅靠增加案例数得到任意步数结论。本轮在 `12b9a60b8aa0339b06c2e9f1b33d48ff5cb67abb` 上增加独立符号模型，检查窗口转移的归纳保持，以及另一组副本身份条件。协议实现与运行策略没有修改。

**结果：23 项正向蕴含、37 项前提一致性检查、14 类故意错误的反例，以及 74 个独立进程 SMT 文件重放全部通过。** 正向义务的反例公式均为 UNSAT；负对照均为 SAT。检查器另有 9 项失败行为回归通过。这里的“独立进程”仍使用同一 Z3 实现，不是不同证明器的交叉认证。

## 窗口层的状态与命题

固定一个已认证、不可变的上下文。W 是窗口大小，h 是接收历史最大序号，f 是接收清理前缀，c 是发送方持久确认前缀，s 是发送方已知清理前缀。支持范围与当前协议整数边界一致：`1 <= W <= 65535`、序号不超过 `2^64-1`，观察时钟不超过 `2^62`。

H 是验证用的历史事实映射，L 是实际语义上的 live 映射，A 是发送方已确认归档的语义映射。事实表示为“序号下标、不透明非零标记”，零表示不存在；不把标记当成 CBOR、签名或真实密文。H 是 ghost state，不能据此宣称接收端实际保存无限历史。

核心不变量为：

\[
0\le s\le f\le c\le h,\qquad h-f\le W,
\]

\[
L[q]=\begin{cases}H[q],&f<q\le h,\\0,&\text{其他},\end{cases}
\qquad 1\le q\le c\Rightarrow A[q]=H[q].
\]

历史前缀 `1..h` 的标记非零。所有前缀和 observed 时间单调不减；旧历史、旧确认归档及已经签发的回执标记不能被改写。

模型还记录三类仅用于验证的历史签发集合：

| 集合 | 归纳不变量 | 为什么需要它 |
|---|---|---|
| R：回执及其事实标记 | R[q] ⇒ `1<=q<=h` 且回执标记为 H[q] | 发送确认依据已签发回执，不假设发送方直接读取接收数据库 |
| O：清理提议的目标 | O[t] ⇒ `1<=t<=c` | 接收方依据历史合法提议，不直接读取当前发送方确认前缀 |
| K：检查点前缀 | K[t] ⇒ `0<=t<=f` | 旧检查点可以低于当前 floor，但不能令发送方 floor 倒退 |

这些集合表示“曾合法签发”，并不代表每份消息现在都已送达或仍可获得。丢包不会使安全不变量失效；可达性和活性没有由集合存在推出。base、root、challenge、scope 和签名校验在这里被抽象为合法签发前提，尚未在 SMT 中证明。

空初态满足关系。每个正向转移分别检查：前态不变量与合法守卫是否推出后态不变量，以及旧前缀保留关系。转移包括按 h+1 接收、从 live 事实签发回执、确认下一个回执、签发提议、应用历史提议、签发/接收检查点、旧提议重试、满窗口/已清理交付/其他业务拒绝、事务前拒绝和无权威效果的退出。

提交后回复丢失表示“已经执行提交转移，随后回复处理不再改变权威”。它不表示提交回滚，也不能由一次方法不可用直接选定旧状态；提交前/后究竟对应哪条抽象路径，仍由实际提交边界的精化负责。这里没有把调用失败统一当成无状态效果。

`retire_issued_offer` 的守卫只要求 target 大于当前 f、O[target] 成立及合法时钟；由历史签发集合与 c 的单调性推出 target 不超过当前 c。它没有把“接收方知道发送方当前数据库”作为接口能力。`confirm_next_receipt` 同理由 R 的历史关系推出合法下一事实。真实实现可能在一次确认事务中折叠多个连续事实；把这个循环对应为若干抽象确认步仍是实现映射义务。

初态和逐步保持义务按普通归纳，支持**该抽象转移系统的任意有限步数**内窗口容量、前缀顺序和已确认事实保留。正向查询没有把操作数限制为 2，也没有枚举到某个深度。它们仍受显式的协议整数上界和上述转移定义约束；这不是任意 Python 程序或所有公开输入的精化定理。

## 副本层是另一组条件义务

副本模型单独记录当前权威代数 g、不可变历史映射 M、当地代数 l 和当地镜像标记 i。无 anchor 的新副本使用 l=-1：

\[
J\equiv g\ge0\land\bigl(l=-1\lor(0\le l\le g\land i=M[l])\bigr).
\]

由 J 与 `l=g` 推出 `i=M[g]`。候选从当地代数 p=l 生成，并要求 CAS 时 p=g；成功提交仅新增 M[g+1]，权威前进后留下旧当地副本仍满足 J，但该副本不再通过当前代数守卫。恢复原子安装 `(k,M[k])`；如果其间权威已前进且 k<g，安装的快照不成为新鲜性租约。

这一模型中的镜像只是不可解释标记，**任意候选镜像满足窗口不变量并未在副本模型中证明**。窗口模型和副本模型当前分别检查，尚未把真实序列化镜像的 decode/encode、候选生成、CAS 与窗口转移机械组合为同一个系统证明。实际的代数身份还依赖 namespace、seq、digest 与镜像核验，不能把这个抽象结论改写为“只检查 seq 即可”。

非回滚权威、历史代数/镜像绑定不可变、镜像和 anchor 原子安装均是明确前提。故意让 g 回退会得到反例；这说明认证不能替代非回滚假设，而不是证明部署已经满足该假设。

## 反例和检查器可信边界

14 类负对照包括：省略容量守卫、删除但不推进 floor、推进 floor 但不删除、没有合法提议就清理、复活已清理事实、改写旧事实、删除发送归档、接受倒退检查点、清空 live 后重置 high、忽略拒绝时钟、忽略当前副本守卫、只恢复镜像而不恢复 anchor、省略 CAS 比较及权威回滚。

例如，`h=1,f=0,c=1,W=1,target=1` 时，只删除 L[1] 而不推进 f 会立即违反 live 后缀关系。若 `c=0`，同一接收历史并不允许无提议清理到 1。副本反例中，权威代数 1 的镜像标记为 4、当地代数 0 的标记为 3；内部一致的旧镜像仍不是当前镜像。这些是抽象模型的反例，不是新的生产缺陷声明。

每项义务先检查前提 SAT，防止矛盾前提导致空真；随后检查“前提且否定结论”。初次不加见证的一个可满足性查询超时，失败日志保留在本地，未写成通过证据。最终仅对需要 SAT 的查询提供具体 ghost 数组和小标量见证，以证明前提一致或给出错误反例。**所有正向 UNSAT 归纳查询都不使用这些见证替换或小边界。**

检查器回归特意给出假命题“所有 W>=1 都满足 W<=3”，同时提供 W=1 见证；检查器仍找到 W>3 的反例并判定该证明失败。此外，空前提、UNKNOWN、缺失/重复义务、错置预期结果、收窄正向查询、篡改文件和路径越界都不能通过。

依赖固定为 [Z3 4.13.3.0](https://pypi.org/project/z3-solver/4.13.3.0/)，上游为 [Z3Prover/z3](https://github.com/Z3Prover/z3)。本轮采用 Python API 导出 SMT-LIB，再逐份启动 Z3 CLI 重放。74 份原始查询及结果都保留；UNKNOWN、超时和非预期返回值均失败。此流程依赖求解器正确性，没有增加独立证明内核的证书检查。
