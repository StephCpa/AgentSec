# 修复公开模拟器的失败边界

本轮对 PR #4 基线 `3bd175496fae4d39a156d3b2f8161b9ac2f2d065` 增加异常输入检查，发现构造性生成器和轨迹校验器在两个调用边界上过度接受：请求超过 8192 字节，或 peer 证书指纹不是 32 字节时，真实 `handle_public` 接口抛出 `GW_FRAME`，不返回签名响应；候选生成器却签发普通 REJECTED，校验器也能接受人为提供的这类签名响应。

另一个故障注入负例发现：真实网关只将明确列出的调度/策略拒绝转为正常 REJECTED，而模型原先会吞掉预测分派抛出的任意 `Rejected`。注入 `STORAGE_INTEGRITY` 等未知错误时，模型因而可能制造真实服务不会返回的正常响应。这里的内部错误为主动注入的负对照，并非声称正常运行中已经出现该存储故障。

## 修复后的分类

| 输入或失败位置 | 真实接口行为 | 生成器与校验器 |
|---|---|---|
| 原始请求长度 >8192，或 peer 长度 ≠32 | 调用前抛出 GW_FRAME，无签名响应 | 在认证和签名之前拒绝该调用；不能生成或接受虚构的普通拒绝 |
| 空请求、恰为 8192 字节但无法解析的请求 | 认证失败，签名 REJECTED，sequence=0 | 保持同样报文，不把帧内语法错误误判为调用帧错误 |
| 32 字节但不匹配的证书指纹、请求签名错误 | 认证失败，签名 REJECTED，sequence=0 | 保持一致 |
| 合法请求封装中的非法 payload | 纯输入解析映射为 GW_PAYLOAD，写入有序拒绝记录 | 保持一致，不改变已有输入验证规则 |
| 策略拒绝、动作证明的签名域错误 | 已声明的拒绝类别，回滚业务效果后保存签名拒绝 | 保持一致；错误证明不消费挑战，随后合法证明仍可成功 |
| 预测分派中的未知 Rejected | 真实对应错误不在 PUBLIC_DENIALS 时中止，不写正常拒绝记录 | 回滚预测效果并使模拟/校验失败，不调用签名服务或添加普通记录 |

模型的正常拒绝集合取真实网关 `PUBLIC_DENIALS`，另加模型内部用来表示明确公开策略分支的 `PUBLIC_DENIED`。这个内部标识不扩充真实服务的拒绝列表。认证阶段与分派阶段保留不同边界，不把所有解析异常或所有内部失败统一为一个状态。

精确重试仍先经过调用帧与实时认证检查。错误长度的 peer 不能借已缓存 request_id 绕过检查；合法精确重试可以在原请求创建窗口结束后返回原始签名字节，不重新签名或重新执行。

## 验证方法

新增 8 项回归测试使用真实持久化网关，并将正常响应与生成报文逐字节比较，同时检查 R1–R4 状态关系。负例直接调用真实接口验证中止行为，再确认生成器没有产生响应、调用签名接口或污染缓存；校验器必须拒绝人工构造但签名有效的虚假响应。

未知错误测试在真实分派和模型分派中先设置暂停状态，再抛出注入异常，核对两边业务效果回滚。已声明拒绝的正对照使用同样的部分效果，验证回滚之后仍正常保存有序拒绝。这样区分了“全部异常都抛出”和“全部异常都签名拒绝”两种错误实现。

新增测试也在临时副本中针对修改前的两个模型模块运行，以保留修复前失败证据。真实协议实现没有修改。既有构造实验与逐步状态实验需针对修改后源码重新执行，旧报告继续绑定旧源码，不能沿用旧摘要声称新版本已经验证。

本轮已完成以下验证，证据和源码摘要见[清单](public-failure-evidence-20261026/manifest.json)：

- 修复前版本运行新增 8 项测试时出现 7 个预期失败/子失败；修复后全部通过。分别保存[基线日志](public-failure-evidence-20261026/baseline-tests.log)及[校验器前后对照](public-failure-evidence-20261026/checker-before-after.json)。
- 最终隔离副本中，57 项仓库回归与 17 项既有公开轨迹测试通过，见[运行记录](public-failure-evidence-20261026/run.json)。
- 修改后源码重新完成 200 案例构造实验、200 案例离线重放，以及同一案例矩阵的逐步实验，共 35,136 个状态边界；这些重叠验证不能相加当作独立样本。
- 既有合法输入的全部轨迹摘要与 R1–R4 投影摘要保持不变，见[交叉核对](public-failure-evidence-20261026/comparison.json)。新的构造实验目录可直接使用 README 的离线重放命令。

PR #4 基线的 Python 3.9 固定依赖和 Python 3.12 升级依赖 CI 均已成功；本轮修复自身的完整 CI 由后续 PR 单独执行，不与基线结果混用。

## 仍未完成的义务

本轮对齐的是 `handle_public` 的调用结果分类，不是定义网络连接失败的完整观察协议。模拟器遇到不支持的失败时终止，只说明它没有伪造成功对应，不能据此证明失败是否与私有数据独立。

任意公开输入的归纳、资源耗尽、真实崩溃/恢复、签名服务可用性、物理时间和网络断连观察仍需继续。生成器仍共享公共转换规则与编解码器，条件化轨迹相等也不构成完整输出分布或端到端 DP 证明。
