# 对 8a35b4b 审核的修复记录

审核输入为用户提供的完整审查文本，固定提交为 `8a35b4bfb42009e8a309db44ef120e3a86bcb52d`。本次修复针对 F1、F2、D1；未下载审查附件，因此不把审查者的额外实验日志当成本次自行取得的证据。

## F1：凭证命名空间

新持久身份为 `(tenant, root, kind, issuer_kid, credential_id)`。其中 `kind` 明确区分根 Grant 和下级 Delegation。登记、同链重复检查、冲突判定、撤销墓碑及恢复审计均采用这个身份。同一身份仍绑定唯一原始签名字节；改变策略、主体或父摘要不能替换原凭证。父链和累计上限账户继续绑定完整凭证摘要，保护域和所有祖先预算仍为合取条件。

可信撤销接口必须显式提供完整范围：

```python
ledger.revoke_credential(
    't', 'workergrant', root_id='root',
    kind='delegation', issuer_kid=b'manager',
)
```

不保留裸 ID 撤销兼容入口。尚未出示的凭证可以提前撤销；相同名称在其他根、类型、签发密钥下不受影响。密钥登记依旧不可覆盖，新 kid 是新签发身份，不是原身份换内容；它不重置保护域账户或链中未变的祖先账户。根权威在线轮换仍不支持。

数据库结构发生不兼容变化。新代码打开旧裸 ID 主键数据库时拒绝 `CREDENTIAL_NAMESPACE_SCHEMA_MISMATCH`；新副本恢复旧见证镜像时由精确 schema 对比拒绝。没有自动迁移，也不能删除旧账本后对同一人群重新发放预算。未来迁移必须保留原操作、随机带、费用、凭证字节、全部撤销以及见证历史，并对旧裸 ID 墓碑指定明确解释。本次没有实现该迁移。

回归覆盖跨根名称抢占、独立根权威、同链跨签发者同名、同一身份内容替换、预撤销隔离、恢复后的链和费用绑定、身份索引篡改、旧结构拒绝，以及新签发密钥不能突破已有祖先预算。篡改测试是显式的可信管理面故障注入。

## F2：公开响应接受集合

CHALLENGE audience 必须等于 `mixed-gateway-v1`。CDDL 明确区分 `journal-sequence`（0 至 2^63−1）、已登记请求序号和操作序号（1 至 2^63−1）、cursor（0 至 2^63−1）。客户端和服务器签名前都拒绝越界 journal sequence；非 REJECTED 成功响应不能使用序号 0。

POLL 的 publication/final 合法组合直接列入 CDDL。FINAL 页内序号连续及 cursor 等于末条序号属于额外语义约束，写入契约注释并由验证器检查。CHALLENGE 的期限上界仍为 2^62，区别于公开请求时钟的严格小于 2^62。

`tests/vectors/public-responses.json` 提供 37 个合成签名正反字节向量，覆盖 audience、各整数边界、POLL 组合和 FINAL 页规则，便于后续第二种实现复用。目前没有运行独立 CDDL 引擎，不声称已经完成跨实现互操作验收。

## D1：草稿预测期限

票据预测加入已计算的 `authorization_expiry`，从而包含整条链的凭证及 issuer/subject 密钥期限。草稿的凭证索引同步采用 F1 的身份元组。

新增测试从真实签名公开请求、真实见证账本、逻辑调度槽及接收确认构造轨迹。根权威、manager、worker、leaf 密钥分别在 110 到期时，真实票据及预测均限于 110；长期有效对照为 160。109 时仍可准入，110 时拒绝新的准入。校验阶段禁止调用 `sqlite3.connect`，用于捕获意外数据库访问。此有限测试不是任意私有状态访问的证明。

适配器仍是未完整验收的研究草稿：仅考虑轨迹期间静态密钥/凭证登记与撤销事实，既有公开 root 控制除外；动态管理面变更、清理事件、一般故障计划、独立编码器和全分布精化仍未覆盖。接收 ACK 与发送方持久确认是两个不同事件，测试显式记录二者。公开调度槽和确认事件来自可信实验驱动，不能从轮询报文推断。

## 验证及证据约定

`scripts/verify.py` 把代码复制到临时目录，在副本中运行原测试入口、新回归和可选模型检查，集中保存日志、生成报告和源码 SHA-256，避免覆盖仓库内历史结果。它会拒绝覆盖已有证据目录。

```sh
python3 scripts/verify.py --models --output /tmp/agentsec-verification-new
```

GitHub Actions 分别配置 Python 3.9 + 固定 cryptography 49.0.0，以及 Python 3.12 + 安装时最新 cryptography 的兼容性检查；每次报告记录实际版本。配置 CI 不等于已观察所有 CI 作业通过，执行状态以 GitHub Actions 和证据目录为准。
